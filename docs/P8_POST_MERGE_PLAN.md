# P8-Dマージ後フォローアップ計画

## 目的と現在地

P8-D「再現可能な実ゲーム画面3場面」はPR #22として`main`へマージ済みです。本計画は、P8-D後の文書整合と、公開前に残る確認を順序立てて記録するdocumentation-onlyの計画です。

P8-DのPR #22 merge前最終CI成功はrun #89（workflow/run ID `31691934450`）で、source headは`92f4b74dad427be01027ab490db74aaf607d4492`、tested merge SHAは`949bd8ec7b1a23a221b4d39902a2317adda94078`です。自動runとartifactは再現性を示す証拠ですが、実機確認、手動受入、初見確認、動画、公開品質、公開承認とは別のものとして扱います。

## 5つの視点

| 視点 | 確認する問い | 受入時の証拠 |
|---|---|---|
| PM | 何が完了し、何が公開判断に残っているか | P8-Dのmerge記録、未完了項目、公開判断の境界がREADME・確認票・台帳で一致している |
| Creator | 候補ページの画面・説明・動画・権利表示が制作物として説明可能か | 配信正本、紹介動画、権利台帳、公開直前の権利確認を同じ版として追跡できる |
| Designer | 初見の利用者が目的、動物の違い、操作、危険を誤解しないか | P4〜P7の初見確認と候補ページの手動確認が完了し、未確認事項が合格扱いになっていない |
| Senior Engineer | CI証拠と配信物の対応、端末別の技術的成立性は確認できるか | 配信正本とartifactを再照合し、source head・tested merge SHA・寸法・状態・容量・入口を記録できる |
| Adversarial | 自動成功を実機・公開品質と取り違えていないか、証拠の抜けや矛盾はないか | 独立した再確認で、未確認項目の隠れた合格扱い、版の取り違え、権利・動画・端末証拠の欠落がない |

## 受入条件

次の全てを満たすまで、公開品質の完了とは判定しない。

- P8-Dの配信正本（候補ページが参照する3枚）とrun #89のCI artifact `p8-gameplay-media`を再照合する。artifactの面・状態・寸法・非空・容量と、配信正本の参照先を突き合わせ、差異があれば断定や黙認をせず記録して判断する。
- run #89の`p8-public-audit`について、candidate gzip 353,069 bytes、入口、依存ライセンス（61パッケージ、UNKNOWN 0）を、source headとtested merge SHAを含めて追跡できる。自動監査の成功を実機確認や公開品質の証拠へ拡張しない。
- P4〜P7のmanual/device/first-view確認を完了し、候補ページの目的、操作、3種類の動物、補助設定、未確認事項の表示を初見で確認する。
- iPhone 17 Pro、iPhone 11 Pro、iPad Pro 2018、PCで表示・性能・入力を確認し、目標端末の実機スクリーンショット3枚以上を別証拠として残す。開発Chromiumの画像を実機証拠の代わりにしない。
- 15〜30秒の紹介動画を確認し、動画で使う画面・音・名称・ロゴ・素材を制作物台帳と権利情報へ照合する。公開直前には推移依存を含むライセンス一覧も固定版と再照合する。
- 上記の証拠を、担当者と別の最終独立レビューで確認し、未解決の矛盾・欠落・誤認表示がないことを記録する。
- 最終独立レビュー後に、ユーザーが次の操作を個別に明示承認する：Draft PRのReady化、merge、GitHub Pages等のpublic公開。承認がない操作は実行しない。

## 次の順序

1. **P8-D配信正本とartifactの再照合**：候補ページの3枚、run #89の`p8-gameplay-media`、run #89の`p8-public-audit`、source head、tested merge SHAを同じ表で対応付ける。
2. **P4〜P7のmanual/device/first-view確認**：各節目の手動受入、初見、実機・性能確認を確認票へ記録し、自動runの成功と分離する。
3. **target device evidence**：指定4端末で画面・性能・入力を確認し、実機スクリーンショットと測定条件を保存する。
4. **video/rights**：15〜30秒の紹介動画を確認し、固定版、動画、候補ページ、制作物・権利台帳、推移依存ライセンスを照合する。
5. **final independent review**：PM/Creator/Designer/Senior Engineer/Adversarialの観点で、未完了項目の残り方、証拠の版、公開境界を独立確認する。
6. **user approvals**：Ready化、merge、public公開をそれぞれ別の承認対象として提示し、明示されたものだけを実行する。

## 対象外

この計画と対応PRでは、次を変更・実行しない。

- ゲーム挙動、状態遷移、入力、描画、保存形式の変更
- 本番hook、撮影用hook、公開入口の追加
- GitHub Pages等へのpublic公開、検索掲載、一般共有
- 本PRのReady化、merge、またはそれらを自動化する設定

画像・コード・既存仕様の固定値は変更せず、確認記録と後続計画だけを更新する。
