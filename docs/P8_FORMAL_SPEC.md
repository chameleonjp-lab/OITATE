# P8「公開候補版」正式仕様

## 目的

P8は、P7までに作ったゲームを公開候補として説明できる形に整える。ゲームの面数や動物を増やす工程ではない。公開前に必要な説明、権利情報、対応範囲、既知問題を、プレイヤーが確認できる状態にする。

## 公開候補ページ

- 確認用ページのソースは `public/candidate.html` とする。
- Vite配信後のURLは `candidate.html` とする。
- ゲーム本体は `?p7=1` で起動する。
- 候補ページからゲーム本体へ、相対リンクで移動できる。
- ページは外部画像、外部フォント、解析、アカウント、通信を使わない。
- 候補ページは公開可能と判定するページではなく、公開前確認のためのページである。

## 必須の表示内容

- ゲーム名と150文字以内の紹介文。
- ゲームの目的と、主人公の立ち位置・誘導音・威嚇音の説明。
- 臆病種、追従種、危険種の違い。
- 横画面、iPhone・iPad・PCの対応方針。
- 音、振動、補助設定、音なしでも遊べる表示の説明。
- 使用OSSと自作制作物の権利表示。
- 既知の未確認事項と、候補ページが最終公開版ではないこと。
- ゲーム開始、正式文書、更新履歴への導線。

## 制作物の扱い

候補ページのヒーローには、ゲームの中心を説明する自作SVGの構図イメージを掲載する。ゲームプレイ欄には、P7の実レンダラー・実UI・実シミュレーションをChromiumの開発実行で再現して取得したPNGを掲載する。開発環境の実ゲーム画面は、目標端末の実機スクリーンショットや実機の表示・性能・入力確認とは別の証拠として扱う。紹介映像はP8後続作業で作成・確認する。

## P8-D 実ゲーム画面の再現取得

P8-Dでは、候補ページでゲーム内容を具体的に伝えるため、次の3場面を同じPlaywright手順から取得する。

- 面1「接近圧力」：主人公の立ち位置と臆病種の反応
- 面2「誘導音と経路」：誘導音を受けた追従種と橋・水場
- 面3「危険管理」：狙いの予告が出た危険種と保護対象

画像は1280×720、表示倍率1で取得し、各2MiB以下、3枚合計6MiB以下とする。取得時には面番号、動物の反応状態、画像の寸法、空画像でないこと、容量を検査し、`metadata.json`と`report.md`をCI artifact `p8-gameplay-media`へ保存する。再現手順は`docs/P8_MEDIA_CAPTURE.md`へ記録する。

この工程で確認できるのは開発Chromium上の実ゲーム画面である。iPhone、iPad、PCの実機表示・性能・入力、実機スクリーンショット、初見プレイ、紹介映像、公開承認は未完了として残す。

## 既存ゲームへの影響

- `?p1-probe=1`、`?p5=1`、`?p6=1`、`?p7=1`の既存入口を変更しない。
- P7の進行保存、得点、記録、面条件を変更しない。
- 新しい動物、オンライン機能、広告、課金、アカウントを追加しない。

## P8-Aの受入条件

- 候補ページが表示され、横方向のはみ出しがない。
- ゲーム開始リンクが`?p7=1`へ正しく移動する。
- 操作、3種類の動物、対応端末、補助設定、権利、既知問題をページ上で確認できる。
- 画像が外部通信なしで表示される。
- 既存の型確認、単体試験、ビルド、ブラウザ試験が通過する。
- P8の実機・公開品質・最終素材確認が未完了であることを隠さない。

## P8-B 公開前測定基盤

P8-Bでは、実機・性能・再開・保存の確認結果を、個人情報や外部送信なしで記録できるようにする。

- 開発サーバーで`?p8-check=1`を付けた場合だけ、診断JSONの保存とリセットを表示する。
- 診断JSONには、画面サイズ、端末ブラウザの識別情報、表示倍率、性能の要約、固定更新の遅延破棄、再開要求、P7の状態、状態遷移の記録を含める。
- 診断JSONは端末内で作成し、ゲームから外部へ送信しない。
- 本番ビルドでは`?p8-check=1`を指定しても診断APIと保存操作を表示しない。
- 診断JSONの保存は、公開用の記録保存やランキングではない。

### P8-Bの受入条件

- 開発時の`?p8-check=1`で、測定中の表示、診断JSONの保存、測定リセットが使える。
- 診断JSONがJSONとして読み取れ、未定義値を含まない。
- 通常の`?p7=1`と本番ビルドへ診断操作を表示しない。
- 型確認、単体試験、ビルド、ブラウザ試験が通過する。
- 実機スクリーンショット、紹介映像、目標端末の実測、推移依存を含むライセンス確認は未完了のまま記録する。

## P8-C 公開前証跡基盤

P8-Cでは、公開候補の容量・初期読み込み対象・依存パッケージの権利情報を、GitHub Actionsで同じ手順から再生成できるようにする。これは実機確認や公開判定の代わりではなく、公開前に確認すべき技術情報を取りこぼさないための証跡である。

- Viteの`dist/.vite/manifest.json`をゲーム入口のバンドル資産の正本として扱い、HTMLの静的参照確認で実ファイルの存在も照合する。
- `index.html`と`candidate.html`から到達できるローカルファイルを追跡する。`srcset`、`poster`、SVG参照、CSS `@import`、CSS `url()`を検査対象に含める。
- 入口ごとの到達closureをgzip換算15MiB以下で判定し、dist全体の容量は参考情報として残す。
- `npm ls --all --include=dev --json`の終了コード、JSON、`problems`、宣言済み依存の欠落、依存ノードのpathとmanifestの不整合を確認する。どれか一つでも不完全なら成功にしない。
- 実際にインストールされた直接依存・開発依存・推移依存のパッケージ名、版、区分、ライセンスを記録し、`UNKNOWN`を大文字小文字に関係なく失敗にする。
- `source head SHA`と`tested merge SHA`を分け、結果JSONとMarkdownへ記録する。
- `vite preview`を使うE2Eで要求失敗、4xx/5xx、画像読み込み失敗、console error、page errorを確認する。
- 結果はCI artifact `p8-public-audit`へ必ず保存し、生成物がない場合もCIを失敗させる。監査成功だけでは、指定端末の性能、画面、音、入力、画像、動画、公開承認を合格にしない。

### P8-Cの受入条件

- 監査スクリプトの単体試験が通過する。
- 本番ビルド後に監査が実行され、JSONとMarkdownが生成される。
- 入口2つの到達ファイルと、入口ごとのgzip換算容量が記録される。
- Vite manifestの欠落、HTML/CSS/SVGの欠落参照、入口ごとの15MiB超過が失敗になる。
- npm lsの非ゼロ終了、JSON不正、problems、宣言済み依存の欠落、manifest不整合が失敗になる。
- 直接依存と推移依存のライセンス一覧が記録され、不明ライセンスがない。
- source head SHAとtested merge SHAが分けて記録される。
- CI artifactへ監査結果が必ず保存される。
- vite previewのE2Eが要求・画像・console・page errorを検査する。
- 実機確認、実ゲーム画像、紹介映像、公開直前の最終権利確認は未完了として残る。
- P8-Dの実ゲーム画面3枚は、実機確認とは分けて再現取得・候補ページ反映を確認する。
