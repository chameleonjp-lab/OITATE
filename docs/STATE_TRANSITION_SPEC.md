# OITATE 状態遷移仕様

- 文書版：1.0
- 作成日：2026年8月9日
- 対象リポジトリ：`chameleonjp-lab/OITATE`
- 文書状態：実装時に必ず従う正式仕様
- 上位文書：`docs/IMPLEMENTATION_CONTRACT.md`
- 目的：動物の状態を一つの値へ詰め込まず、同時に起きる心理、目的、移動、収容を矛盾なく処理する

---

## 0. 適用規則

本書は、動物、群れ、危険種、囲い、救助の状態を実装する際の正式な状態遷移表である。

`GAME_DESIGN_MASTER_PLAN.md`または`IMPLEMENTATION_PLAN.md`の状態一覧と食い違う場合は、本書を優先する。ただし、得点、入力、時間、衝突の正式規則は`IMPLEMENTATION_CONTRACT.md`を優先する。

---

## 1. 状態を4層に分ける理由

動物は同時に複数の状況を持つ。

例として追従種は、次の状態を同時に持ち得る。

- 活動中である。
- 主人公を追従している。
- 危険種を見て警戒している。
- 囲い入口で先頭の通行を待っている。

これを一つの状態だけで管理すると、経路を探し直している間は捕食者から逃げない、追従中は緊張できない、といった矛盾が起きる。

そのため、すべての動物は次の4層を持つ。

| 層 | 役割 |
|---|---|
| 生存・収容層 | その個体がゲーム上有効か、救助中か、収容済みかを管理する |
| 行動目的層 | 何を目標に動くかを管理する |
| 心理層 | 平静、警戒、混乱を管理する |
| 移動層 | 停止、移動、入口待ち、再探索、自動復帰を管理する |

この4層に加え、危険種は攻撃段階を別に持つ。群れ全体は個体とは別の群れ状態を持つ。

---

## 2. 共通データ

各動物は、最低限次を持つ。

| 項目 | 内容 |
|---|---|
| `animalId` | 1プレイ中に重複しない識別子 |
| `speciesId` | 臆病種、追従種、危険種などの種類 |
| `groupId` | 所属する群れ。危険種は単独群れでもよい |
| `lifeState` | 生存・収容層 |
| `intentState` | 行動目的層 |
| `emotionState` | 心理層 |
| `locomotionState` | 移動層 |
| `stressValue` | 0〜100の緊張値 |
| `stressPrimaryCause` | 現在もっとも強い緊張原因 |
| `stressSecondaryCauses` | 補助原因 |
| `targetEntityId` | 現在追う主人公、動物、囲いなど |
| `targetPosition` | 現在の目的地点 |
| `pathStatus` | 経路の有効性 |
| `penReservationId` | 入口通行権 |
| `lastSafePosition` | 場外復帰用の安全位置 |
| `stateEnteredAt` | 各状態へ入った固定更新番号 |
| `signalMemory` | 受信した合図と有効期限 |
| `eventGroupId` | 連続出来事をまとめる識別子 |

### 2.1 時間の基準

状態時間は画面描画の時刻ではなく、固定間隔のシミュレーション更新番号で管理する。

- 初期値は1秒20回の固定更新とする。
- 一時停止中は固定更新を進めない。
- 入力は次の固定更新へ取り込む。
- 状態の開始と終了は固定更新番号で記録する。

## 3. 生存・収容層

### 3.1 状態一覧

| 状態 | 意味 |
|---|---|
| `active` | 通常の判断と移動を行う |
| `rescuePending` | 攻撃を受け、救助を待っている |
| `enteringPen` | 正しい囲いの確定線を越え、収容動作中 |
| `captured` | 収容済み。外部の判断と道順から除外する |
| `autoRecovering` | 技術的な場外や不正位置から復帰中 |
| `failureLocked` | 失敗確定後。表示以外を停止する |

### 3.2 遷移表

| 現在 | 条件 | 次 | 処理 |
|---|---|---|---|
| `active` | 保護対象へ最初の有効攻撃 | `rescuePending` | 救助期限3秒、移動停止、救助出来事開始 |
| `active` | 正しい囲いの収容条件成立 | `enteringPen` | 入口予約維持、収容動作開始 |
| `active` | 技術的な場外または不正位置 | `autoRecovering` | 攻撃、収容、得点を一時無効化 |
| `rescuePending` | 救助成功 | `active` | 緊張を最低55へ、1秒保護時間、救助出来事終了 |
| `rescuePending` | 救助期限切れ | `failureLocked` | プレイ失敗確定 |
| `rescuePending` | 別の保護対象が攻撃される | `failureLocked` | プレイ失敗確定 |
| `enteringPen` | 収容動作完了 | `captured` | 経路、入口予約、外部衝突を解除 |
| `enteringPen` | 囲い条件が壊れる | `active` | 収容を取り消し、入口前へ戻す |
| `autoRecovering` | 安全位置へ復帰完了 | `active` | 0.5秒の移動保護後に通常判断へ戻る |
| 任意 | プレイ失敗確定 | `failureLocked` | すべての判断と移動を停止 |

### 3.3 割り込み規則

- `captured`は他のすべての状態より優先する。
- `rescuePending`中は、追従、群れ復帰、収容へ移らない。
- `autoRecovering`中は、捕食対象、収容対象、得点対象にならない。
- `enteringPen`中でも、技術的な場外が起きた場合は`autoRecovering`を優先する。
- `failureLocked`から他の状態へ戻さない。再挑戦では新しい1プレイを作る。

## 4. 行動目的層

### 4.1 共通状態

| 状態 | 目的 |
|---|---|
| `idle` | その場で待つ、短い通常動作を行う |
| `wander` | 種類の通常範囲内をゆっくり移動する |
| `regroup` | 群れの主要群へ戻る |
| `fleePlayer` | 主人公の接近圧力から離れる |
| `followPlayer` | 誘導音により主人公を追う |
| `fleePredator` | 危険種から安全な方向へ逃げる |
| `approachPen` | 正しい囲いの入口へ進む |
| `penBackoff` | 間違った囲いまたは詰まりから後退する |
| `predatorHunt` | 危険種が保護対象を探し追う |
| `predatorChasePlayer` | 威嚇音により危険種が主人公を追う |
| `none` | 生存・収容層が判断を止める状態 |

### 4.2 目的の選択順

`lifeState=active`の場合、次の順で目的を選ぶ。

1. 即時地形危険からの回避
2. 危険種からの逃走
3. 救助に関わる危険種の主人公追跡
4. 有効な威嚇音
5. 有効な誘導音
6. 接近圧力
7. 正しい囲いへの進入
8. 群れへの復帰
9. 通常移動または待機

危険種では次の順を使う。

1. 収容条件
2. 飛びかかり、狙い、攻撃後回復
3. 救助用威嚇音
4. 通常の威嚇音
5. 有効な保護対象の追跡
6. 索敵

### 4.3 臆病種の遷移

| 現在 | 条件 | 次 | 終了条件 |
|---|---|---|---|
| `idle`/`wander` | 危険種を視認 | `fleePredator` | 危険種を2秒見失い、安全経路を確保 |
| 任意 | 緊迫範囲の主人公 | `fleePlayer` | 主人公が誘導範囲外へ1秒以上離れる |
| `idle`/`wander` | 誘導範囲の主人公 | `fleePlayer` | 主人公が注意範囲外へ離れる |
| 任意 | 威嚇音を受信 | `fleePlayer` | 短い散開時間が終了 |
| `idle`/`wander` | 群れの主要群から基準以上離れる | `regroup` | 主要群へ戻る、または危険で中断 |
| `fleePlayer`/`regroup` | 正しい囲い入口が進行方向にある | `approachPen` | 収容条件成立、危険発生、経路消失 |
| `approachPen` | 間違った囲いの警告区域 | `penBackoff` | 後退距離を満たす |
| 任意 | 高い優先の条件がない | `idle`または`wander` | 新しい条件発生 |

### 4.4 追従種の遷移

| 現在 | 条件 | 次 | 終了条件 |
|---|---|---|---|
| `idle`/`wander` | 誘導音を受信 | `followPlayer` | 5秒経過、威嚇音、距離超過、危険発生 |
| `followPlayer` | 誘導音を再受信 | `followPlayer` | 残り時間を5秒へ更新 |
| 任意 | 危険種を視認 | `fleePredator` | 危険種を2秒見失う |
| `followPlayer` | 主人公から離れすぎる | `regroup` | 主要群へ戻る、誘導音再受信 |
| `followPlayer`/`regroup` | 正しい囲い入口が進行方向にある | `approachPen` | 収容条件成立、危険発生、経路消失 |
| 任意 | 威嚇音を受信 | `idle` | 追従時間を解除し、短時間待機 |
| `approachPen` | 間違った囲いの警告区域 | `penBackoff` | 後退距離を満たす |

### 4.5 危険種の遷移

危険種の目的と攻撃段階は分けて管理する。

| 現在目的 | 条件 | 次目的 |
|---|---|---|
| `predatorHunt` | 通常の威嚇音が有効 | `predatorChasePlayer` |
| `predatorChasePlayer` | 4秒経過、主人公へ接触、主人公経路消失 | `predatorHunt` |
| `predatorHunt` | 有効な保護対象を発見 | `predatorHunt`のまま対象設定 |
| 任意 | 危険種収容条件成立 | `none` |
| 任意 | 攻撃後回復中 | 現目的を保持するが移動停止 |

## 5. 心理層

### 5.1 状態一覧

| 状態 | 行動への影響 |
|---|---|
| `calm` | 通常の旋回と合図反応 |
| `alert` | 速度を少し上げ、予備動作を強くする |
| `panic` | 最低1.5秒、細かな誘導を受け付けず安全方向へ逃げる |
| `notApplicable` | 危険種など、保護対象用の緊張を使わない種類 |

### 5.2 遷移

| 現在 | 条件 | 次 |
|---|---|---|
| `calm` | 緊張45以上 | `alert` |
| `alert` | 緊張30以下 | `calm` |
| `alert` | 緊張85以上 | `panic` |
| `panic` | 1.5秒以上経過かつ緊張55以下 | `alert` |
| `panic` | 緊張30以下になっても最低時間未満 | `panic`を維持 |

### 5.3 混乱中の入力

`panic`中は次を無視または弱める。

- 誘導音による細かな追従方向
- 主人公の誘導範囲による微調整
- 囲い入口への自動吸着

次は常に有効とする。

- 崖、壁、場外の回避
- 危険種からの逃走
- 動物同士の最低距離
- 閉じた門と進入禁止区域

### 5.4 緊張出来事のまとめ方

同じ主原因で緊張60以上が続く間は、一つの出来事とする。

- 60未満へ1秒以上戻った後、再び60以上になった場合は新しい出来事とする。
- 主原因が変わった場合は、前の出来事を終了し、新しい出来事を開始する。
- 危険種が原因の高緊張は危険管理へ、主人公圧力や威嚇音が原因の高緊張は安全へ帰属する。

## 6. 移動層

### 6.1 状態一覧

| 状態 | 意味 |
|---|---|
| `stopped` | 速度0または停止動作 |
| `moving` | 有効な目的地または進行方向へ移動中 |
| `waitingForEntrance` | 囲い入口の通行権を待っている |
| `repathing` | 現在の経路が無効で、道を探し直している |
| `backingOff` | 入口、壁、詰まりから横または後方へ離れる |
| `recoveringPosition` | 場外や不正位置から安全位置へ戻る |

### 6.2 遷移

| 現在 | 条件 | 次 | 最大時間 |
|---|---|---|---:|
| `stopped` | 有効な目的地がある | `moving` | なし |
| `moving` | 入口予約が他個体にある | `waitingForEntrance` | 2秒 |
| `waitingForEntrance` | 予約取得 | `moving` | なし |
| `waitingForEntrance` | 2秒進展なし | `backingOff` | 1秒程度 |
| `moving` | 経路が無効 | `repathing` | 0.5秒を目標 |
| `repathing` | 新経路取得 | `moving` | なし |
| `repathing` | 経路を取得できない | `backingOff`または`stopped` | 1秒 |
| 任意 | 同じ障害へ3秒以上押し続ける | `backingOff` | 1秒程度 |
| 任意 | 場外、不正高さ、進入禁止内部 | `recoveringPosition` | 2秒以内 |
| `recoveringPosition` | 安全位置へ戻る | `stopped` | 0.5秒保護 |

### 6.3 進展の判定

詰まり判定は速度だけでなく、目的地までの距離が減っているかで判断する。

- 0.5秒ごとに目的地距離を比較する。
- 1秒で基準距離以上近づいていれば進展ありとする。
- 他個体との安全な待機は詰まりとして数えない。
- 入口予約待ちは専用状態として扱う。

## 7. 危険種の攻撃段階

### 7.1 状態一覧

| 状態 | 意味 |
|---|---|
| `search` | 攻撃可能な保護対象を探す |
| `chase` | 対象へ経路移動する |
| `aim` | 姿勢を低くし、飛びかかりを予告する |
| `lunge` | 短い直線攻撃を行う |
| `recovery` | 攻撃後に停止する |
| `disabled` | 収容済みまたは失敗確定 |

### 7.2 対象として有効な条件

次をすべて満たす保護対象だけを選ぶ。

- `lifeState=active`
- 危険種から視認可能
- 攻撃可能区域にいる
- 経路が存在する
- 収容済み、説明用、場外復帰中ではない
- 1秒の救助後保護時間が終了している

### 7.3 遷移表

| 現在 | 条件 | 次 | 処理 |
|---|---|---|---|
| `search` | 有効対象を発見 | `chase` | 対象と危険出来事グループを設定 |
| `chase` | 攻撃距離内、視線あり、経路あり | `aim` | 1.2秒予告開始、警告表示 |
| `chase` | 対象喪失 | `search` | 2秒の対象記憶後に出来事終了 |
| `chase` | 威嚇音が有効 | `search` | 保護対象を解除し主人公追跡へ切替 |
| `aim` | 1.2秒経過、視線と経路を再確認 | `lunge` | 直線攻撃開始 |
| `aim` | 壁、対象喪失、威嚇音、経路消失 | `chase`または`search` | 予告を解除 |
| `lunge` | 保護対象へ有効接触 | `recovery` | 救助待ちまたは失敗確定 |
| `lunge` | 主人公へ接触 | `recovery` | 主人公よろめき、注意解除 |
| `lunge` | 壁または最大距離へ到達 | `recovery` | 攻撃失敗 |
| `recovery` | 1秒経過 | `search` | 索敵再開 |
| 任意 | 危険種収容確定 | `disabled` | すべての対象と警告を解除 |
| 任意 | プレイ失敗確定 | `disabled` | 移動と判定停止 |

### 7.4 威嚇音で主人公を追う間

威嚇音の効果中は攻撃段階を次のように扱う。

- `aim`中に威嚇音が届いた場合は`aim`を中断する。
- `lunge`開始後は原則中断しない。
- 主人公を追跡中は、保護対象への`aim`へ入らない。
- 主人公へ接触した時点で効果を解除し、`recovery`へ入る。
- 効果終了後1.75秒は通常の威嚇音へ反応しない。
- 救助用の威嚇音は同じ救助出来事で1回だけ耐性を無視できる。

## 8. 救助の状態遷移

### 8.1 救助出来事

保護対象への最初の有効攻撃で、一つの救助出来事を作る。

| 項目 | 内容 |
|---|---|
| `rescueEventId` | 一意な識別子 |
| `victimAnimalId` | 救助対象 |
| `predatorId` | 攻撃した危険種 |
| `startedAt` | 開始固定更新 |
| `deadlineAt` | 3秒後の固定更新 |
| `rescueOverrideUsed` | 耐性無視の威嚇音を使ったか |
| `result` | 成功、期限切れ、別対象攻撃、再攻撃 |

### 8.2 救助成功

次のいずれかで救助できる。

- 救助対象を攻撃した危険種へ、救助用威嚇音が届く。
- 主人公が救助影響範囲へ入り、危険種が主人公を有効対象として認識する。

成功時は次を行う。

- 被害対象を`active`へ戻す。
- 緊張値を最低55へする。
- 1秒の再攻撃保護を付ける。
- 危険種を主人公追跡または攻撃後回復へ移す。
- 救助出来事を成功で終了する。
- 安全評価の救助減点を一度だけ記録する。

### 8.3 救助失敗

次のいずれかで失敗確定する。

- 期限切れ。
- 救助中に別の保護対象へ有効攻撃。
- 同じ対象が再攻撃保護終了後に再び有効攻撃。

失敗確定後は、すべての動物を`failureLocked`、危険種を`disabled`へ移す。

## 9. 群れ状態

個体とは別に、群れ全体へ次を持たせる。

| 項目 | 内容 |
|---|---|
| `groupId` | 群れ識別子 |
| `speciesId` | 種類 |
| `activeMembers` | 活動中の個体 |
| `mainClusterMembers` | 主要群に属する個体 |
| `strayMembers` | 基準距離以上離れた個体 |
| `groupCenter` | 主要群の中心 |
| `groupHeading` | 主要群の進行方向 |
| `currentGoal` | 主人公、囲い、待機場所など |
| `splitState` | 一体、分裂候補、分裂確定、再結合中 |
| `cameraPriorityUntil` | カメラ対象保持期限 |

### 9.1 群れ分裂

| 状態 | 条件 |
|---|---|
| `cohesive` | 基準距離外の個体がない、または短時間だけ |
| `splitCandidate` | 1体以上が基準距離外へ出る |
| `splitConfirmed` | 3秒以上、主要群から離れた状態が続く |
| `rejoining` | 離れた個体が主要群へ近づいている |

得点の群れ分裂は`splitConfirmed`へ入った時点で一度だけ記録する。

### 9.2 分裂の原因

群れ分裂の主原因を次から記録する。

- 主人公の接近圧力
- 威嚇音
- 主人公の移動速度超過
- 危険種からの逃走
- 地形による経路分離
- 入口待ち
- 不明または技術的な詰まり

危険種が主原因なら危険管理、主人公誘導や経路が主原因なら統率へ帰属する。入口待ちは通常、減点しない。

## 10. 囲い状態

各囲いは次を持つ。

| 状態 | 意味 |
|---|---|
| `open` | 通常の進入が可能 |
| `reservingEntrance` | 先頭個体へ通行権を与えている |
| `closing` | 危険種の捕獲門を閉鎖中 |
| `closed` | 危険種収容済みで通行不可 |
| `disabled` | プレイ終了または説明専用 |

### 10.1 通常囲い

- 通常囲いは閉鎖状態を使わなくてもよい。
- 一つの入口につき予約は一つだけとする。
- 予約個体が2秒進展しない場合は解除する。
- 収容中へ入った個体が完了するまで、後続を確定線へ入れない。

### 10.2 危険種囲い

| 現在 | 条件 | 次 |
|---|---|---|
| `open` | 危険種の中心が内側確定線を越える | `reservingEntrance` |
| `reservingEntrance` | 全身が内部、主人公が逃げ道から外へ出る、0.6秒留まる | `closing` |
| `reservingEntrance` | 危険種が外へ戻る | `open` |
| `closing` | 同じ固定更新で通行禁止を有効化 | `closed` |
| `closed` | なし | `closed`を維持 |

門の見た目が閉じるより前に、すり抜け可能な時間を作らない。判定上の閉鎖と演出開始を同じ更新で行う。

## 11. 合図の記憶

各動物は合図ごとに次を持つ。

| 項目 | 内容 |
|---|---|
| `signalType` | 誘導音、威嚇音、救助用威嚇音 |
| `receivedAt` | 受信更新 |
| `expiresAt` | 効果終了更新 |
| `sourcePlayerId` | 主人公識別子 |
| `accepted` | 行動へ採用したか |
| `blockedReason` | 壁、耐性、低い優先、範囲外など |
| `eventId` | 出来事識別子 |

### 11.1 重ね掛け

- 誘導音は残り時間を5秒まで更新し、加算しない。
- 威嚇音は残り時間を4秒まで更新し、加算しない。
- 再使用待ち中でもボタン入力は受け取れるが、発動せず、待ち表示を返す。
- 受信したが優先順位で採用されなかった合図は、行動目的を変えない。

## 12. 出来事一覧

最低限、次を一度だけ記録する。

| 出来事 | 開始 | 終了または確定 |
|---|---|---|
| `stressEpisode` | 緊張60以上 | 1秒以上60未満、または主原因変更 |
| `panicEpisode` | 心理が`panic`へ入る | `alert`へ戻る |
| `groupSplit` | 群れが`splitConfirmed`へ入る | 再結合完了 |
| `wrongPenGuidance` | 警告区域へ1秒滞在 | 後退開始 |
| `predatorExposure` | 視認と経路が成立 | 対象喪失2秒、収容、プレイ終了 |
| `predatorAim` | `aim`開始 | 中断または`lunge`開始 |
| `rescue` | 最初の有効攻撃 | 成功または失敗 |
| `normalCapture` | 正しい収容条件成立 | 収容済み |
| `predatorCapture` | 危険種収容5条件成立 | 門閉鎖と同時に確定 |
| `autoRecovery` | 場外、不正位置 | 安全位置復帰 |
| `inputCancellation` | 合図を押下 | 外へ滑らせて離す、または中断 |

### 12.1 重複防止

- 同じ出来事識別子を二度記録しない。
- 同じ動物、同じ囲いの誤誘導は5秒以内を一つにまとめる。
- 同じ主原因の高緊張は、終了条件まで一つにまとめる。
- 危険種の同一追跡は、対象を失い2秒経過するまで同じ出来事とする。
- 状態を同じ値へ再設定しただけでは出来事を作らない。

## 13. 1固定更新の処理順

毎固定更新は次の順で処理する。

1. プレイ全体の進行状態を確認する。
2. 入力を取り込む。
3. 合図の発動、取り消し、再使用待ちを更新する。
4. 地形、視認、音、危険、囲いを観測する。
5. 生存・収容層の最優先遷移を処理する。
6. 危険種の攻撃段階を処理する。
7. 緊張値と心理層を更新する。
8. 行動目的を優先順位で選ぶ。
9. 群れ状態と入口予約を更新する。
10. 経路と移動層を更新する。
11. 位置と向きを更新する。
12. 攻撃、収容、場外を確定する。
13. 出来事記録を確定する。
14. 得点用の時間と集計値を更新する。
15. 表示側へ状態差分を渡す。

同じ固定更新内で、収容確定した動物を攻撃対象にしない。攻撃判定より前に収容の候補を検出し、最終確定の競合を優先規則で解決する。

---

## 14. 同時発生の解決規則

### 14.1 収容と攻撃が同時の場合

- 収容5条件または通常収容4条件が、攻撃接触より前の位置更新で成立していた場合は収容を優先する。
- 同じ位置更新で両方が初めて成立した場合は、攻撃予告が完了済みなら攻撃を優先する。
- 判定順に依存しないよう、候補を集めてから一度だけ解決する。

### 14.2 威嚇音と飛びかかり開始が同時の場合

- `aim`完了前に威嚇音が受理された場合は飛びかかりを中断する。
- `lunge`開始が確定した後は中断しない。
- どちらが先かは固定更新番号と入力受付順で決め、画面更新時刻へ依存しない。

### 14.3 救助成功と期限切れが同時の場合

期限更新より前に救助入力が受理されていた場合は救助成功を優先する。期限を過ぎた後に受理した入力は失敗とする。

### 14.4 門閉鎖と主人公の位置

門閉鎖条件を確定する時点で、主人公が閉鎖区域外にいることを確認する。閉鎖開始後に主人公が門へ戻っても通過できない。

## 15. 表示へ渡す状態

表示側は内部状態を直接推測しない。シミュレーションから次の表示状態を受け取る。

| 表示状態 | 主な内部条件 |
|---|---|
| 通常 | `active`かつ`calm` |
| 警戒 | `alert` |
| 混乱 | `panic` |
| 合図受理 | 合図を`accepted=true`で受信 |
| 合図拒否 | 壁、耐性、再使用待ち、低優先で不採用 |
| 危険視認 | `fleePredator`または危険曝露中 |
| 攻撃予告 | 危険種が`aim` |
| 救助待ち | `rescuePending` |
| 囲い進入 | `enteringPen` |
| 収容済み | `captured` |
| 詰まり復帰 | `backingOff`または`repathing` |

予備動作はPR 3とPR 4の仮モデル段階から実装し、PR 6まで後回しにしない。

## 16. 保存と再現

状態の保存または診断出力には次を含める。

- 4層状態
- 危険種の攻撃段階
- 各状態の開始更新
- 緊張値と主原因
- 合図の有効期限と耐性
- 入口予約
- 救助期限と保護時間
- 危険出来事グループ
- 群れの主要群と離脱個体
- 経路の識別子と目的地

表示モデル、音、粒子の途中状態は、論理再現に不要な場合は保存しなくてよい。

## 17. 状態試験

最低限、次を自動試験する。

### 17.1 生存・収容

- `captured`から`active`へ戻らない。
- `rescuePending`中に収容されない。
- `autoRecovering`中に攻撃、収容、得点が成立しない。
- 失敗確定後に状態が進まない。

### 17.2 心理

- 緊張44では警戒へ入らない。
- 45で警戒へ入る。
- 警戒中、31では平静へ戻らない。
- 30で平静へ戻る。
- 85で混乱へ入る。
- 混乱は1.5秒未満で終了しない。
- 55を超えたまま混乱から戻らない。

### 17.3 合図

- 誘導音を重ねても5秒を超えて加算しない。
- 威嚇音を重ねても4秒を超えて加算しない。
- 耐性中の通常威嚇を採用しない。
- 同じ救助で耐性無視を2回使えない。
- 壁指定がある場合、音を受信しない。

### 17.4 危険種

- 視線がない対象へ`aim`へ入らない。
- `aim`中に壁が入ると中断する。
- `lunge`開始後の判定が画面更新速度で変わらない。
- 収容済み危険種が`search`へ戻らない。
- 主人公接触でゲームオーバーにしない。

### 17.5 囲い

- 正しい囲いで4条件を満たさなければ収容しない。
- 間違った囲いで収容しない。
- 同じ誤誘導を5秒以内に二重記録しない。
- 入口予約を同時に2体へ与えない。
- 危険種の5条件を満たした更新で門通行を無効化する。

### 17.6 群れ

- 分裂候補から3秒未満で分裂減点しない。
- 入口待ちを群れ分裂の主原因にしない。
- 危険種逃走が主原因の場合、統率へ重複減点しない。

## 18. 実装レビュー時の確認表

各動物関連PRでは、次を確認する。

- 4層状態が独立しているか。
- 一つの状態変更が他層を不要に上書きしていないか。
- 開始条件と終了条件が両方あるか。
- 永久に終わらない状態へ最大時間または脱出条件があるか。
- 状態の競合が固定更新順に依存していないか。
- 同じ出来事を複数回記録していないか。
- 表示側が内部状態を独自に推測していないか。
- 一時停止、やり直し、画面非表示で状態が正しく解除されるか。

## 19. 変更管理

この状態遷移を変更する場合は、該当PRに次を記載する。

1. 変更する状態または遷移。
2. 変更理由。
3. ゲーム性への影響。
4. 得点への影響。
5. 既存の診断データと再現性への影響。
6. 追加または修正する試験。

状態を減らす場合も、単に実装が難しいという理由だけで削除しない。より単純で同じゲーム上の役割を果たす代案を示す。
