# P8実装契約

## 1. ページ構成

- `public/candidate.html` をViteの`public`配下から静的に配信する。
- CSSは`candidate.css`に分離し、外部フォントや外部CSSを読み込まない。
- 画像は`public/media`内の自作SVGまたは、実ゲームの開発実行から取得した自作PNGを相対参照する。外部素材や第三者画像は使わない。
- ゲーム本体への導線は`./?p7=1`とし、配信先のサブパスでも壊れない相対URLを使う。

## 2. 表示とアクセシビリティ

- 見出しの階層を崩さない。
- 画像には内容を説明する`alt`を付ける。
- 色だけで動物の種類や重要な状態を伝えない。
- キーボード操作でリンクとページ内移動を使えるようにする。
- 画面幅が狭い場合も横スクロールを発生させない。
- 動きのある表現は候補ページへ必須にしない。`prefers-reduced-motion`を尊重する。

## 3. 権利と通信

- Herdy Gerdyの名称、ロゴ、画像、比較画像を候補ページへ掲載しない。
- 外部URLへの必須通信を作らない。
- 個人情報、端末固有識別子、広告識別子、プレイ記録の外部送信を追加しない。
- 直接依存のライセンスは`P8_PRODUCTION_INVENTORY.md`へ記録する。
- 自作SVG、HTML、CSSは外部素材を含まないことを記録する。

## 4. ゲーム回帰

- P8の候補ページ追加で、ゲーム本体のDOM、入力、状態遷移、保存形式を変更しない。
- `?p7=1`の既存E2Eを通過させる。
- 既知の未確認事項は、合格扱いにせずページとPRへ表示する。

## 5. 後続で必須の確認

- 候補ページ用に、実ゲーム実行から再現可能に取得した画像3枚以上を掲載する。開発用Chromiumでの取得を認めるが、取得条件と状態を`docs/P8_MEDIA_CAPTURE.md`へ記録する。
- 目標端末での表示・性能・入力確認を行い、その証跡として実機スクリーンショット3枚以上を別に残す。開発用Chromium画像をこの項目の代わりにしない。
- 15〜30秒の紹介映像。
- iPhone 17 Pro、iPhone 11 Pro、iPad Pro 2018、PCでの性能・画面・入力確認。
- 公開直前の推移依存を含むライセンス確認。

## 6. 開発時診断

- `src/quality/p8-diagnostics.ts`は、フレーム時間、遅延破棄時間、状態遷移を端末内で一時的に記録する。
- `?p8-check=1`はViteの開発時だけ有効とし、E2E用の状態操作を本番へ公開しない。
- 診断レポートへ個人名、連絡先、端末固有識別子、プレイ記録の外部送信先を含めない。
- 保存ボタンはJSONファイルを端末へダウンロードするだけで、サーバー通信を開始しない。
- P8-Bの診断レポートは実機確認の証拠を補助する。実機での操作、性能、画面、音、振動の確認を自動合格にはしない。

## 7. 公開前監査

- `scripts/audit-public-build.mjs`はNode.js標準機能だけで公開ビルドと依存ツリーを監査する。
- Viteの`dist/.vite/manifest.json`をゲーム入口のバンドル資産の正本とし、`index.html`と`candidate.html`の静的参照も照合する。
- HTMLの`src`、`href`、`srcset`、`poster`、SVG参照、CSSの`@import`と`url()`を検査し、存在しないローカル参照をエラーにする。
- 入口ごとの到達closureをgzip換算15MiB以下で判定し、dist全体の容量は参考値として残す。
- npm ls --all --include=dev --jsonの非ゼロ終了、JSON不正、problems、宣言済み依存の欠落、依存ノードのpathとmanifestの不整合を成功扱いしない。npmがoptionalとして示す、現在のOSへ入らない依存は実際にインストールされた一覧へ含めない。
- 実際にインストールされた直接依存・開発依存・推移依存のライセンス情報を記録し、`UNKNOWN`（大文字小文字違いを含む）を失敗にする。
- `source head SHA`と`tested merge SHA`を分けて記録する。監査結果は`artifacts/p8-public-audit/report.json`と`report.md`へ出力し、CI artifactへ必ず保存する。生成物がない場合はartifact保存も失敗させる。
- `vite preview`を使うE2Eで要求失敗、4xx/5xx、画像読み込み失敗、console error、page errorを確認する。
- 監査はネットワーク通信、外部送信、アカウント、ゲーム保存を追加しない。
- 監査成功は、実機性能、読み込み体感、画面、音、入力、画像、映像、公開の合格を意味しない。

## 8. P8-D撮影と証跡

- 撮影は`?p7=1&p7-e2e=1`の開発用入口でだけ行い、本番ビルドへ撮影用APIを公開しない。
- `prepareMediaScene`は既存のP7/P5シミュレーションと描画を使って到達可能な状態を準備する。撮影専用の偽DOM、合成画像、外部素材は追加しない。
- コミット済みPNGを候補ページの配信正本とし、CI artifact `p8-gameplay-media`は同じ手順の再生成証跡として扱う。
- WebGL、GPU、フォントなどの差があるため、生成PNGのバイト完全一致は要求しない。面・状態・寸法・非空画面・容量を自動検査し、視覚差はPRで確認する。
