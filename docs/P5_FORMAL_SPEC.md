# P5 縦切り統合版 正式仕様

- 文書版：1.0
- 文書状態：P5実装の範囲・数値・受入条件
- 上位計画：`docs/PRODUCER_MASTER_PLAN.md`のP5
- 対応契約：`docs/P5_IMPLEMENTATION_CONTRACT.md`
- プレイテスト票：`docs/P5_PLAYTEST.md`

## 1. 目的と範囲

P5は、P2〜P4で個別に確認した誘導、群れ、地形、危険の要素を、1つの検証画面へ統合する。画面は`?p5=1`で開く。P3とP4の画面・シミュレーション・開発APIは回帰互換のため残す。

含めるものは次の通り。

- 臆病種6体 `coward-1`〜`coward-6`。
- 追従種4体 `follower-1`〜`follower-4`。
- 危険種1体 `predator-1`。
- 3種類に対応する3つの囲い。
- 浅い水、狭い橋、迂回路の地形差。
- 動物の性質に合わせた安全な経路と速い経路。
- 危険種の威嚇、攻撃予告、短い救助機会。
- 収容数、経路発見、失敗理由を表示する仮の結果画面。
- 失敗後の同じ配置からの即時再挑戦。

対象外は、得点の細部、称号、完成素材、複数ステージ、Navmesh、オンライン保存、公開品質の合格である。P5では仮表示の結果を作るが、正式な評価記録はP6で固定する。

P4手動受入はユーザー承認により未確認のまま、P5の実装と自動検査へ進む。この例外はP5の合格を意味しない。

## 2. 固定する登場要素

| 種類 | 数 | 基本反応 | 対応する囲い |
|---|---:|---|---|
| 臆病種 | 6 | 主人公から逃げ、群れへ戻る。浅い水を避ける | 西の囲い |
| 追従種 | 4 | 誘導音の後、主人公を追う。浅い水を通れる | 東の囲い |
| 危険種 | 1 | 保護対象を追い、威嚇音で主人公を追う | 中央の囲い |

危険種の保護対象は、臆病種のうち最も近い`coward-1`とする。保護対象を別の動物として追加せず、合計11体を維持する。

## 3. 地形と複数経路

中央の浅い水場は、東西の迂回路と中央の狭い橋で越えられる。

- **安全な経路**：水場を避けて外周を回る。臆病種も通れるが、移動距離は長い。
- **速い経路**：狭い橋を通って水場を短く越える。追従種と危険種は通れる。臆病種は橋へ入らず、安全な経路へ戻る。

同じ囲いへ向かう方法を一つに固定しない。臆病種を速い経路へ無理に押し込むことは正解にしない。追従種は誘導音の発動位置と橋の選択によって、速い経路を使える。

経路の発見は、動物が経路の識別区画を通過した時点で記録する。安全・速いの両方を発見した状態は、画面と結果画面で確認できる。

## 4. 状態と数値

基準値は`src/game/p5-vertical-slice-simulation.ts`の`P5_TUNING`と一致させる。

| 項目 | 正式値 |
|---|---:|
| 判断更新 | 20Hz（0.05秒） |
| 臆病種の数 | 6体 |
| 追従種の数 | 4体 |
| 危険種の数 | 1体 |
| 群れの個体間距離 | 1.15m以上を目標 |
| 臆病種の誘導距離 | 3.5m |
| 追従時間 | 4秒 |
| 危険種の攻撃予告 | 1.2秒 |
| 救助期限 | 3秒 |
| 救助後の再攻撃保護 | 1秒 |
| 収容確定保持 | 0.6秒 |
| 走行の速度補正 | 歩行の1.35倍 |
| 世界の判定範囲 | -16.5m〜16.5m |

動物の位置、向き、状態、時間は固定更新で進める。描画は固定更新の結果を補間する。`deltaSeconds <= 0`または非有限値では状態を進めない。

## 5. 収容と危険

臆病種は主人公の反対側へ逃げ、囲い入口へ近づくと入口予約を使って一体ずつ収容する。追従種は誘導音の有効時間中、主人公の後方へ移動する。危険種は`search`、`chase`、`aim`、`lunge`、`recovery`、`chasePlayer`、`disabled`を使う。

危険種の狙い開始から飛びかかりまでは1.2秒とする。狙い中に威嚇音を受けると主人公追跡へ移り、飛びかかり開始後は中断しない。最初の有効攻撃で保護対象を救助待ちにし、3秒以内に威嚇音または主人公接近で救助できる。救助後の有効な再攻撃は失敗とする。

攻撃は、視線が柵や閉鎖地形で遮られた対象、収容済み対象、救助後保護中の対象には成立させない。

全11体が対応する囲いへ収容され、危険種が隔離された場合にクリアする。攻撃が再成立した場合または救助期限を過ぎた場合に失敗する。詰まりは動物の待機・後退処理で回復し、技術的な位置破綻を失敗として扱わない。

## 6. 画面表示と結果

P5画面には、次を常時表示する。

- 3種類の収容数。
- 危険種の状態と保護対象の状態。
- 安全な経路・速い経路の発見状態。
- 動物の性質を短く伝える説明。

クリアまたは失敗時は仮の結果画面を表示する。結果には、収容数、発見した経路、失敗理由、再挑戦ボタンを出す。得点や称号はP5で確定しない。

## 7. P5受入条件

自動検査と手動プレイの受入条件を分ける。

### 自動検査

- 3種類11体が固定IDで作られる。
- 臆病種は水場を避け、追従種は狭い橋を通れる。
- 安全な経路と速い経路が別々に記録される。
- 狙いは1.2秒未満で飛びかからない。
- 狙い中の威嚇音で攻撃を中断できる。
- 救助成功、救助期限切れ、救助後の再攻撃失敗を再現できる。
- 11体収容と仮結果画面、再挑戦を実ブラウザ経路で確認する。
- P3・P4・P1の既存回帰が成功する。

### 手動受入

プロデューサー計画のP5条件として、初見5〜8人を目安に次を確認する。

- 60〜80%が12分以内にクリアできる。
- 80%以上が3種類の違いを一つ以上説明できる。
- 80%以上が失敗時に次へ変える行動を一つ説明できる。
- 安全な経路と速い経路の両方を発見または利用できる。
- カメラ・入力が原因の失敗が全試行の10%未満である。

自動検査の成功、CIの成功、Draft PRの作成は、手動受入やP4手動受入の合格を意味しない。

## 8. 変更境界

3種類の数、経路の役割、攻撃予告、救助期限、収容条件、失敗条件を変更する場合は、本書と実装契約を同じ作業単位で更新する。得点の正式計算、完成素材、2面目、オンライン保存を追加する場合はP6以降の別判断とする。
