# P2 面白さ試作 プレイテスト

この手順は、P2の中心である「主人公の位置で臆病種の反応を読み、反対方向へ逃がして囲いへ入れる」面白さだけを確認する。得点、危険種、緊張・混乱、Navcat、完成素材、公開の評価には使わない。

## 対象ビルド

- 横画面のブラウザ版。
- 仮素材の臆病種3体と囲い1つ。
- 主人公の移動とカメラはP1の入力方式を使用する。
- P1入力回帰用の「誘導」「威嚇」は通常画面では隠れている。`?p1-probe=1`を明示した開発確認時だけ表示し、P2の動物へ効果を与えない。
- 収容は動物の全身が囲い内側へ入り、0.35秒以上留まった場合に確定する。
- 3体収容後に「もう一度試す」で初期状態へ戻る。
- 入口では技術的な重なりを防ぐ簡易ロックだけを使う。2秒の進展監視と詰まり復帰を含む正式な入口予約はP3の範囲とし、この試験では評価しない。

## 初見テスト（5人前後）

テスターへゲームの攻略方法を先に説明しない。画面の文章を読んでから開始してもらう。

1. 端末またはブラウザを横画面にし、ページを読み込む。
2. 「開始」などの追加操作は行わず、最初の状態を10秒観察してもらう。
3. 90秒以内に、移動とカメラだけで3体のうち少なくとも2体を、本人が意図した同じ方向へ動かしてもらう。囲いへの収容は試してよいが、必須とは伝えない。
4. テスターが最初に動物を近づけた瞬間から、次を記録する。
   - 意図した方向へ動いたか。
   - 動物が反応する前の「見る／身を引く」が読めたか。
   - 主人公の位置と、動物が逃げた方向の関係を説明できたか。
5. 2体以上が意図した同じ方向へ動いた時点、または90秒経過後、「なぜその方向へ動いたと思うか」を尋ねる。説明を誘導しない。
6. 画面の完了ボタンを指示せず、テスターが自発的にもう一度試すか、位置取りを改善しようとするかを記録する。
7. 2回目は、最初の試行で本人が発見した方法を使ってもらう。開発者は新しいヒントを追加しない。

P2の進行目安は、初見の70%以上が90秒以内に2体以上を意図した同じ方向へ少なくとも1回動かせること、80%以上が主人公の位置と移動方向の関係を説明できること、過半数が指示なしで再挑戦または改善を試みることである。5人で行う場合は順に最低4/5、4/5、3/5とし、人数が5人に満たない場合は合否を判定せず、人数不足として記録する。

## ブラウザ回帰確認

- `npm run typecheck`
- `npm test`
- `npm run build`
- `npm run e2e`
- 画面を縦向きにすると入力が解除され、横向きへ戻して「再開する」まで動かない。
- P2完了後に「もう一度試す」を押すと、3体・主人公・収容数が初期状態へ戻る。
- 開発用の`?p1-probe=1`で合図ボタンを表示して押しても、動物のフェーズ、位置、収容数が変化しない。
- 3体の同時接近で、動物が同一点へ重ならず、囲い入口の予約が1体ずつになる。

## 実機記録の扱い

この文書の未実施欄を自動試験の成功で埋めない。P1のiPhone実機確認とP1合格は未記録であり、P2のブラウザ試験がP1実機合格の代わりになることもない。
