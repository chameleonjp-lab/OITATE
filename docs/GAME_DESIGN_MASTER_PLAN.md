## 0. この文書の位置付け

既存の`IMPLEMENTATION_PLAN.md`は、技術選定、システム構成、実装順序、性能条件を定めた基礎計画として残す。

本書は、その中で不足していた次の内容を具体化する。

- 何を面白さの中心にするか。
- プレイヤーが何を見て、何を考え、何を操作するか。
- 動物ごとの違いを、どのように遊びへ結び付けるか。
- ミスをどのように伝え、どこまで立て直せるようにするか。
- 得点で何を評価し、どのような遊び方を良いプレイとするか。
- iPhoneで、どのように誤操作を減らし、細かな誘導を成立させるか。
- 初回プレイ、繰り返しプレイ、上達後の遊びをどう分けるか。

ゲーム性、操作、得点、難易度、画面表示、音、演出、試験条件については、本書を優先する。技術的な実装方法は、既存の実装計画書を優先する。

## 1. 今回の改訂で解決する問題

既存計画には、3種類の動物、3種類の誘導方法、危険種を先に隔離する順序問題が定義されていた。しかし、それだけでは「正しい順番で作業するゲーム」に留まり、繰り返し遊びたくなる深さが不足する。

今回の改訂では、次の問題を解決する。

| 既存計画の不足 | 改訂後の方針 |
|---|---|
| 動物の反応が、逃げる・付いてくる・追うの二択に近い | 距離、速度、緊張、群れの状態、地形によって反応の強さを連続的に変える |
| 正解手順が一つに固定されやすい | 安全重視、速度重視、難しい近道の複数解を成立させる |
| 危険種への接触が即失敗で、立て直しがない | 攻撃の予備動作と短い救助機会を入れ、原因を理解して対応できるようにする |
| 操作案がボタン配置だけで、誘導の精度が定義されていない | 歩行と走行、圧力の強さ、入力の取り消し、カメラ補正、反応速度まで定める |
| 得点方式が未定 | 安全、統率、判断、速度を別々に評価し、速さだけが最適解にならないようにする |
| 初回説明が短いチュートリアルという記述だけ | 地形と配置で自然に操作を覚える手順を定める |
| 見た目と音が仕上げ工程にまとめられている | 動物の状態を伝える情報として、アニメーション、音、振動を設計に含める |
| 面白さの完成条件が曖昧 | 初回理解、再挑戦、得点改善、複数解、理不尽な失敗の有無を判定条件にする |

## 2. ゲームの目標体験

### 2.1 プレイヤーが演じる役割

主人公は、動物を直接操作する人物ではない。動物の性質を読み、進みたい方向の反対側へ回り込み、適切な合図を出して群れ全体を導く「誘導士」とする。

プレイヤーに感じてもらう中心は、次の一文で表す。

> 動物の反応を予測し、自分の立ち位置と合図だけで、複数の群れが意図どおりに動いたときの達成感。

### 2.2 ゲームが約束すること

- 動物の反応には理由があり、観察すれば予測できる。
- 同じ入力でも、動物の種類と状況によって結果が変わる。
- 速く動くことより、先回りして位置を取ることが重要になる。
- ミスをしても、すぐ失敗するだけではなく、立て直す判断が生まれる。
- クリア後の評価を見れば、次に何を改善すればよいか分かる。

### 2.3 想定するプレイ時間

最小版の1ステージは、次の長さを目標にする。

| 状態 | 目標時間 |
|---|---:|
| 初回プレイ | 6〜10分 |
| 一度クリアした後 | 4〜6分 |
| 高評価を狙う熟練プレイ | 3〜5分 |

制限時間による強制失敗は設けない。時間は得点の一部としてのみ扱う。

## 3. ゲームデザインの5原則

### 3.1 間接操作だが、結果は予測できる

動物は主人公の命令どおりに即座に動く駒ではない。一方で、完全な気まぐれにもさせない。

動物が反応する前には、主人公を見る、耳を向ける、姿勢を変えるなどの予備動作を入れる。プレイヤーは、入力が届いたか、どの方向へ動きそうかを確認してから次の行動へ進める。

### 3.2 計画と操作の両方で上達できる

ゲームには三つの判断の大きさを持たせる。

- 大きな判断：どの種類を先に収容するか。
- 中くらいの判断：どの経路と待機場所を使うか。
- 細かな操作：群れのどちら側へ立ち、どの速さで近づくか。

知識だけでも、反射神経だけでも高評価にならない構成にする。

### 3.3 失敗は予告し、原因を示し、立て直せる

危険種が画面外から突然攻撃する、壁越しに捕食する、動物がランダムに場外へ出るといった失敗は認めない。

危険が高まったときは、姿勢、音、画面端表示、短いカメラ補助で知らせる。プレイヤーが対応できる時間を設ける。

### 3.4 動物は数値の違う同じ物体にしない

種類ごとに、移動の速さだけではなく、次の違いを持たせる。

- 何を怖がるか。
- 何へ近づくか。
- 仲間との距離をどの程度保つか。
- 緊張するとどう変化するか。
- どの地形を通れるか。
- 囲いへ入るときに何をためらうか。

見た目、動き、音、攻略上の役割を同じ方向へそろえる。

### 3.5 iPhoneで判断を妨げない

小さなボタン、長押し、連打、複数ボタンの同時押しを前提にしない。画面を操作部品で埋めず、重要な動物と進行方向が見えることを優先する。

## 4. プレイの基本循環

1回の誘導は、次の順で進む。

1. **観察する**
   - 動物、囲い、危険種、地形を確認する。
2. **優先順位を決める**
   - 先に隔離すべき危険や、安全に待たせる場所を決める。
3. **位置を取る**
   - 動かしたい方向の反対側へ回り込む。
4. **合図を出す**
   - 接近、誘導音、威嚇音を使い分ける。
5. **反応を待つ**
   - 動物がこちらを見たか、群れがまとまっているかを確認する。
6. **進路を修正する**
   - 走って強く押すか、歩いて細かく向きを変える。
7. **囲いへ収容する**
   - 入口を塞がず、群れが一体ずつ通れる位置を保つ。
8. **次の状況を見直す**
   - 危険種や残りの群れの状態を確認する。

「合図を連打して走り回る」より、「一度止まり、次に必要な位置へ先回りする」方が良い結果になるようにする。

## 5. 主人公の誘導手段

### 5.1 接近による圧力

主人公が近づくことで、臆病な動物が反対方向へ動く。圧力は一つの円ではなく、三段階に分ける。

| 範囲 | 動物の反応 |
|---|---|
| 注意範囲 | 主人公の方向を見る。まだ大きく移動しない |
| 誘導範囲 | 主人公と反対方向へ歩く。細かな方向調整ができる |
| 緊迫範囲 | 走って距離を取る。長く続くと混乱しやすい |

主人公が走っていると圧力を強くし、歩いていると弱くする。これにより、同じ立ち位置でも操作の速さが結果へ影響する。

暫定値は次のとおりとし、実機試験で調整する。

- 注意範囲：5.5m
- 誘導範囲：3.5m
- 緊迫範囲：1.5m
- 走行中の圧力：歩行時の1.35倍

### 5.2 誘導音

誘導音は、追従種へ「主人公を一定時間追う」注意を与える。音を鳴らし続ける操作にはせず、1回の入力で4〜6秒程度の追従状態を作る。

- 反応前に、耳や顔を主人公へ向ける。
- 壁越しには反応しない。
- 仲間から離れすぎた個体は、主人公より群れへの復帰を優先する。
- 再度鳴らすと、追従時間を更新する。
- 反応した個体の上に短い記号を表示する。

### 5.3 威嚇音

威嚇音は、一つの用途だけを持たない。種類によって異なる反応を起こす。

- 臆病種：短時間だけ散開し、主人公から距離を取る。
- 追従種：追従を解除し、近くで待つ。
- 危険種：一定時間、保護対象より主人公を優先して追う。

便利な万能ボタンにはしない。危険種を引きつけるために使った音が、近くの臆病種を危険な方向へ散らす可能性を残す。

### 5.4 落ち着かせる操作

落ち着かせる専用ボタンは追加しない。

主人公が動物から距離を取り、操作を止めると、動物の緊張が下がる。プレイヤーが「何もしないこと」も判断として使えるようにする。

### 5.5 入力の予告と取り消し

誘導音と威嚇音は、ボタンへ指を置いた時点で効果範囲を薄く表示し、指を離したときに発動する。

指をボタンの外へ滑らせてから離すと、入力を取り消せるようにする。誤って触れた瞬間に重要な群れを散らさないためである。

## 6. 動物の共通設計

### 6.1 動物が持つ設定

各種類は、次の項目をデータとして持つ。

| 分類 | 主な設定 |
|---|---|
| 感覚 | 視野、視認距離、音への反応距離、壁の影響 |
| 移動 | 歩行速度、走行速度、旋回速度、停止距離 |
| 群れ | 仲間へ寄る強さ、離れすぎの基準、個体間距離 |
| 緊張 | 上昇量、低下量、混乱する値、回復時間 |
| 誘導 | 接近、誘導音、威嚇音への反応 |
| 危険 | 恐れる相手、追う相手、攻撃対象 |
| 地形 | 通行できる地面、水、狭路、坂、危険区域 |
| 囲い | 対応する囲い、入口でのためらい、収容条件 |

### 6.2 緊張の仕組み

保護対象の動物には、0〜100の緊張値を持たせる。

- 主人公が近すぎる。
- 威嚇音を受ける。
- 危険種を視認する。
- 仲間から離れる。
- 通れない地形へ押され続ける。

このような状況で緊張が上がる。

| 緊張値 | 状態 |
|---:|---|
| 0〜39 | 平静。通常の誘導に正確に反応する |
| 40〜59 | 警戒。速度が少し上がる |
| 60〜84 | 焦り。旋回が大きくなり、群れが崩れやすい |
| 85〜100 | 混乱。短時間、細かな誘導を受け付けず逃走する |

緊張は得点へ影響するが、常に数値で表示しない。姿勢、呼吸、足運び、状態記号で伝える。

### 6.3 個体差

同じ種類でも、全個体が完全に同じ動きをすると機械的に見える。一方で、差が大きいと攻略が不安定になる。

個体差は、速度、警戒しやすさ、仲間へ寄る強さに±10%以内で持たせる。ステージ開始時に固定し、やり直しても同じ個体は同じ傾向を保つ。

重要な通行条件、捕食関係、音への対応は個体差で変えない。

### 6.4 群れ全体と個体を分ける

群れ全体が向かう目標と、個体が近くの仲間を避ける動きを分ける。

- 群れ側：中心位置、進みたい方向、分裂状態、収容目標を管理する。
- 個体側：近づきすぎを避ける、壁を避ける、足元へ沿う。

囲いの入口では、先頭個体に通行権を与え、後続個体が横から割り込まないようにする。入口で全個体が押し合う状態を防ぐ。

## 7. 最小版の3種類

### 7.1 臆病種 6体

役割は、主人公の立ち位置を使う基本的な追い込みである。

- 主人公から逃げる。
- 仲間から離れると群れへ戻ろうとする。
- 威嚇音で大きく散る。
- 浅い水を避ける。
- 緊張が高いと、囲いの入口を通り過ぎやすい。

上手なプレイでは、群れの真後ろから押し続けず、進行方向の外側へ回り込みながら形を整える。

### 7.2 追従種 4体

役割は、音を使った経路選択と隊列管理である。

- 接近圧力への反応は弱い。
- 誘導音を聞くと主人公を追う。
- 威嚇音で追従を解除する。
- 浅い水を通れる。
- 先頭へ集まりすぎると互いに詰まるため、緩い列を作る。

主人公が速く走りすぎると後続が離れ、追従が切れる。最短経路を走るだけではなく、群れの速度に合わせる必要がある。

### 7.3 危険種 1体

役割は、順序判断と緊張を作ることである。

- 保護対象を視認すると追跡する。
- 威嚇音を聞くと、一定時間主人公を優先する。
- 主人公へ追いつくと、短いよろめきを与え、注意が解除される。
- 狭い通り抜け穴を通れない。
- 専用囲いには、主人公だけが抜けられる逃げ道を設ける。

危険種を囲いへ入れる操作は、単に入口へ誘導するだけではなく、主人公が逃げ道を使って外へ抜ける小さな地形パズルにする。

### 7.4 反応の比較

| 入力・状況 | 臆病種 | 追従種 | 危険種 |
|---|---|---|---|
| 主人公の接近 | 反対方向へ移動 | 少し距離を取る | 主人公を警戒する |
| 誘導音 | 一瞬見るが追わない | 主人公を追う | 基本的に無視する |
| 威嚇音 | 散開する | 追従を解除する | 主人公を追う |
| 危険種の接近 | 緊張して逃げる | 群れで逃げる | 対象を追う |
| 浅い水 | 避ける | 通れる | 通れる |
| 狭い抜け道 | 通れる | 通れる | 通れない |

## 8. 危険、攻撃、救助

### 8.1 危険種の攻撃段階

危険種は、接触した瞬間に失敗を成立させない。次の段階を踏む。

1. **索敵**：対象を探す。
2. **追跡**：対象へ近づく。
3. **狙い**：姿勢を低くし、対象を固定する。
4. **飛びかかり**：短い直線移動を行う。

狙いから飛びかかりまでは、最低1.2秒の予告時間を設ける。対象の上、画面端、音の三つで知らせる。

### 8.2 救助状態

最初の攻撃が成立した場合、ただちにゲームオーバーにはしない。

- 保護対象は3秒程度の救助待ち状態になる。
- 危険種へ威嚇音を当てるか、主人公が近づいて注意を引けば救助できる。
- 救助に成功すると動物は復帰するが、安全評価が下がる。
- 救助時間を過ぎるか、同時に別の保護対象が攻撃されると失敗する。

この仕組みによって、事前の計画だけでなく、崩れた後の対応にも技量が表れる。

### 8.3 理不尽な失敗を防ぐ条件

- 壁越しの攻撃を禁止する。
- 経路が存在しない対象を攻撃しない。
- 画面外の危険には、画面端表示を出す。
- 一時停止中は危険判定を進めない。
- 技術的な場外落下は自動復帰させ、不具合をプレイヤーの失敗として扱わない。
- 危険種の狙い動作中に、プレイヤーが取り得る対応を最低一つ残す。

## 9. 囲いの設計

### 9.1 見分け方

囲いは色だけで区別しない。

- 入口の形。
- 地面の模様。
- 旗や看板の記号。
- 対応動物を表す立体的な飾り。
- 収容時の音。

動物側にも同じ記号を使い、対応関係を一目で分かるようにする。

### 9.2 収容の確定

動物が入口へ少し触れただけでは収容しない。囲いの内側にある確定線を越え、進行方向が内側を向いている場合に収容する。

収容後は、動物をその場で消さない。囲いの中へ数歩進み、落ち着く動きを見せる。プレイヤーが成功を確認できるようにする。

### 9.3 間違った囲い

対応しない囲いでは、入口で停止して首を振る、または短く後退する。見えない壁へ押し続ける状態にしない。

間違った囲いへ確定線まで入れた場合は得点を下げるが、ステージを即失敗にはしない。外へ誘導し直せるようにする。

### 9.4 入口の詰まり対策

- 入口は、対象動物の横幅の2.2〜2.8倍を目安にする。
- 先頭個体を予約し、後続は少し間隔を空ける。
- 3秒以上進めない個体は、一度横へ離れて並び直す。
- 主人公が入口中央へ立った場合、画面で「入口を空ける」合図を出す。

## 10. ステージ設計

### 10.1 ステージが持つ三つの問題

一つのステージには、次の三つを含める。

1. **順序の問題**
   - どの種類を先に安全にするか。
2. **経路の問題**
   - 水、狭路、危険区域をどのように避けるか。
3. **操作の問題**
   - 群れの形を崩さず、入口へ向けるか。

一つだけを極端に難しくしない。順序を理解しても操作が不可能、操作が上手でも正解経路が一つしかない、といった状態を避ける。

### 10.2 地形の基本ルール

- 行き止まりには、群れを戻せる十分な幅を用意する。
- 危険種と保護対象の間に、安全に待たせる場所を作る。
- 主要経路には、カメラが地形へ遮られない空間を確保する。
- 正しい操作でも一度入ると出られない場所を作らない。
- 囲いの手前には、群れを整えるための空間を置く。
- 近道には危険や操作難度を持たせ、安全な遠回りも残す。

### 10.3 最小版ステージの構成

最小版は、全機能を一面へ無造作に置かず、空間の順に理解できるようにする。

1. **開始地点の見晴らし台**
   - ステージ開始前に全体を観察できる。
   - 最初の移動まで時間評価を開始しない。
2. **中央の草地**
   - 臆病種と追従種が離れて配置される。
   - 誤って両方へ同時に合図を当てない距離を取る。
3. **危険種の区域**
   - 低い地形で存在は見えるが、すぐ接触しない。
4. **危険種用の囲い**
   - 主人公だけが抜けられる狭い出口を持つ。
5. **浅い水の経路**
   - 追従種は通れるが、臆病種は避ける。
6. **臆病種用の広い囲い**
   - 最後に群れの形を整える十分な前庭を持つ。

### 10.4 複数の解き方

最小版でも、少なくとも二つの有効な手順を用意する。

- **安全な手順**：危険種を先に隔離し、残りを順番に収容する。
- **速い手順**：追従種を安全な待機場所へ移し、その後で危険種を最短経路から囲う。

速い手順は高い操作精度を必要とするが、安全評価を必ず下げる設計にはしない。上級者が安全と速度を両立できる余地を残す。

### 10.5 完成版6ステージ案

名称は暫定とする。

| 面 | 主に覚える内容 | 組み合わせ |
|---|---|---|
| 1：風向きの草地 | 接近圧力と回り込み | 臆病種のみ |
| 2：呼び声の浅瀬 | 誘導音と地形差 | 追従種、浅い水 |
| 3：牙の囲い | 威嚇音、危険予告、救助 | 危険種、専用囲い |
| 4：二つの合図 | 合図の副作用 | 臆病種と追従種が近接 |
| 5：谷間の門 | 群れの分裂と狭路 | 複数の入口、待機場所 |
| 6：大移送 | 全要素と複数解 | 3種類、複数経路、総合評価 |

## 11. iPhoneの操作設計

### 11.1 基本配置

横画面を標準とする。

| 場所 | 操作 |
|---|---|
| 左下の広い領域 | 指を置いた位置に仮想スティックを出し、主人公を動かす |
| 右側の空き領域 | 直接ドラッグしてカメラを回す |
| 右下 | 誘導音ボタン |
| 右下 | 威嚇音ボタン |
| 右上 | カメラを主人公の後方へ戻すボタン |
| 上部 | 一時停止、目的確認 |

固定位置の小さなスティックではなく、左側の広い範囲で動かせる方式を採る。

### 11.2 歩行と走行

別の走行ボタンは置かない。

- スティックを小さく倒す：歩く。
- 大きく倒す：走る。
- 設定で、歩行を広く使う「精密操作」と、走行へ移りやすい「標準」を選べる。

これにより、移動ボタンと走行ボタンの同時押しを不要にする。

### 11.3 ボタンの大きさと反応

- 誘導音と威嚇音は、最低56×56ptを目標にする。
- カメラ復帰と一時停止も、最低44×44ptを確保する。
- 押している状態を、明るさ、拡大、輪郭で示す。
- 音と振動を無効にしていても、押したことが分かる表示を出す。
- 指を離してから発動する。

### 11.4 必須にしない操作

次は、クリアに必須としない。

- 長押し。
- 素早い連打。
- 二つ以上のボタンの同時押し。
- 二本指以上の特別なジェスチャ。
- 端末を傾ける操作。

### 11.5 設定項目

- カメラ感度。
- 自動カメラの強さ。
- 左右反転。
- 左利き用の左右入れ替え。
- 仮想スティックの大きさ。
- 行動ボタンの大きさ。
- 振動の有無と強さ。
- 常時歩行を優先する精密操作。

### 11.6 PC操作

PCでは、移動、カメラ、二つの合図、一時停止、カメラ復帰を、キーボードだけでも操作できるようにする。キーの変更は完成版で対応し、最小版では設定をデータへ分離して後から変更できる構成にする。

## 12. カメラ設計

### 12.1 主人公だけを中央に置かない

主人公だけを追うと、誘導対象が画面外へ出やすい。カメラの注視点は、主人公と現在関わっている群れの中心を混ぜて決める。

暫定比率は次のとおりとする。

- 主人公：65%
- 反応中の群れの中心：35%

主人公と群れが離れると少し引き、近づくと戻す。急な拡大縮小は行わない。

### 12.2 自動補助

- 主人公が進む方向を少し先まで映す。
- 危険種が狙い状態へ入った場合、対象が見える方向へ小さく寄せる。
- 手動回転中は自動補正を弱める。
- 手動操作を止めて1.5秒後から、ゆっくり後方へ戻す。
- 木や壁が遮る場合は、カメラを前へ寄せるか遮る物を透過する。

### 12.3 観察時間

開始直後は、ゲームを動かさずにステージを見渡せる。主人公を初めて動かすか、合図を出した時点でプレイ時間を開始する。

### 12.4 画面酔いへの対応

- カメラ揺れは初期状態で無効にする。
- 自動回転の強さを変更できる。
- 危険時のカメラ移動は、瞬間的な切り替えではなく小さな補助に留める。
- 画面効果を減らす設定を用意する。

## 13. 画面表示と情報の優先順位

### 13.1 通常表示

常に表示する情報は少なくする。

- 種類ごとの残り収容数。
- 現在の主目的。
- 誘導音と威嚇音の使用可能状態。
- 一時停止。

大きな得点数字はプレイ中に表示しない。得点を気にして動物の状態を見失うことを防ぐ。

### 13.2 必要なときだけ表示する情報

- 動物が合図へ反応した記号。
- 緊張が高まった記号。
- 危険種が狙っている対象。
- 画面外にいる危険種と未収容群れの方向。
- 間違った囲いの警告。
- 入口を主人公が塞いでいる警告。

### 13.3 地図

最小版はステージを小さく保ち、常設の小地図を置かない。画面が情報で埋まることを避ける。

次のどちらかが起きた場合に、完成版で簡易地図を追加する。

- 画面外の群れを探す時間が、通常プレイの15%以上になる。
- 初回テストで、目的の囲いを見失う人が3人中2人以上いる。

## 14. 動き、音、振動による反応

### 14.1 入力から反応まで

合図ボタンを離してから100ms以内を目標に、次のいずれかを始める。

- 音の波紋。
- ボタンの反応。
- 対象動物の耳や顔の向き。
- 短い振動。

実際の移動開始が少し遅れる場合でも、入力を受け取ったことはすぐ伝える。

### 14.2 動物の予備動作

- 臆病種：耳を伏せ、重心を逃げる方向へ移す。
- 追従種：主人公を見る、群れの先頭が一歩出る。
- 危険種：姿勢を低くし、狙う対象へ体を向ける。

予備動作は飾りではなく、次の行動を読む情報として使う。

### 14.3 収容時の手応え

- 囲いの記号が一度明るくなる。
- 短い成功音を鳴らす。
- 対応する残数が動物側から表示側へ移る演出を入れる。
- 最後の1体では、通常より少し強い演出を入れる。

長い演出で操作を止めない。

### 14.4 振動

振動は補助情報として使う。

- 合図が正常に発動：短く弱い振動。
- 危険種が狙い状態：異なる二連振動。
- 群れの収容完了：短く明確な振動。

振動だけで重要情報を伝えない。設定で無効化と強さ調整を可能にする。

## 15. 得点方式

### 15.1 得点の目的

得点は、クリアできたかどうかだけでなく、次の改善点を伝えるために使う。

- 動物を安全に扱えたか。
- 群れを崩さず、正しい囲いへ導けたか。
- 危険を早めに管理できたか。
- 必要以上に時間をかけなかったか。

速さの比重は15%に留める。最短時間だけを狙って動物を混乱させる遊びが最高得点にならないようにする。

### 15.2 総得点

総得点は100,000点とする。

| 評価 | 最大点 | 比率 | 主に見る内容 |
|---|---:|---:|---|
| 安全評価 | 40,000 | 40% | 救助、混乱、高緊張、危険への長時間曝露 |
| 統率評価 | 25,000 | 25% | 群れの分裂、間違った囲い、収容の安定 |
| 判断評価 | 20,000 | 20% | 危険種が保護対象を狙える時間、飛びかかり予告の発生 |
| 時間評価 | 15,000 | 15% | ステージ別の目標時間に対する完了時間 |

### 15.3 安全評価

40,000点から始め、次を差し引く。

- 救助状態の発生：1回につき10,000点。
- 混乱状態の発生：1回につき1,200点。
- 緊張値が60以上だった合計時間：1秒につき50点、最大8,000点。

同じ個体が短時間に緊張値を上下した場合は、一つの出来事としてまとめる。数値の揺れで大量に減点しない。

### 15.4 統率評価

次の方式を暫定案とする。

- 基礎点：10,000点。
- 一つの種類を、混乱、誤収容、入口からの逆戻りなしで収容：1種類につき5,000点。
- 間違った囲いへの収容確定：1回につき4,000点減点。
- 群れが基準距離を超えて3秒以上分裂：1回につき1,500点減点。

最大25,000点、最低0点とする。

### 15.5 判断評価

20,000点から始め、次を差し引く。

- 保護対象が、危険種の視認と追跡が成立する区域にいた時間：1秒につき100点。
- 危険種が保護対象へ飛びかかる予備動作を始めた：1回につき2,000点。

「危険種を最初に囲ったか」という決め打ちでは評価しない。別の安全な手順でも高得点を取れるよう、実際に生じた危険で評価する。

### 15.6 時間評価

ステージごとに、テスト結果から次の二つを定める。

- 標準目標時間`parTime`。
- ゆっくり完了した場合の基準`slowTime`。

暫定式は次のとおりとする。

- `parTime`以内：15,000点。
- `slowTime`以上：3,000点。
- その間：3,000〜15,000点を緩やかな曲線で減らす。

初回の観察時間と一時停止時間は、操作時間へ含めない。将来オンライン順位を導入する場合は、別に実時間も記録する。

### 15.7 評価段階

| 評価 | 条件 |
|---|---|
| S | 90,000点以上、救助なし、誤収容なし |
| A | 75,000点以上 |
| B | 60,000点以上 |
| C | クリア |

合計点だけでS評価を取れない条件を設ける。動物を危険にさらして時間だけ短くする方法を防ぐ。

### 15.8 追加称号

得点とは別に、プレイ内容を短い称号で示す。

- 全員無傷：救助状態なし。
- 混乱なし：保護対象が混乱状態にならない。
- 誤収容なし：間違った囲いへ入れない。
- 先読み：危険への曝露時間が基準以下。
- 快速：標準目標時間以内。

称号は、得点の理由を分かりやすくするために使う。

### 15.9 結果画面

結果画面には、合計点だけでなく4項目の内訳を出す。

例：

- 安全：36,800 / 40,000
- 統率：21,000 / 25,000
- 判断：17,400 / 20,000
- 時間：9,200 / 15,000

その下に、次回改善する内容を一つだけ表示する。

例：

> 臆病種が長く緊張していました。群れの後ろから少し距離を取ると、安全評価が上がります。

一度に多くの指摘を出さない。

### 15.10 得点の不正な稼ぎ方を防ぐ

- 同じ救助を繰り返して加点しない。
- 合図の使用回数だけでは減点しない。安全のために必要な合図をためらわせないためである。
- 動物を意図的に分裂させて再結合しても加点しない。
- 収容直前のやり直しで得点状態だけが残らないようにする。
- 固定ステージでは初期配置と個体差を固定し、比較条件を同じにする。

### 15.11 保存

最小版では端末内に次を保存する。

- 最高総得点。
- 最高評価。
- 最短操作時間。
- 安全評価の最高値。
- 取得した称号。
- 使用した補助設定。

オンラインランキングは、ゲーム単体の面白さ、得点の公平性、不正対策を確認した後に判断する。

## 16. 難易度と補助

### 16.1 難しさを速度だけで上げない

難易度は、次の四つを分けて調整する。

- 判断の複雑さ：種類と危険の組み合わせ。
- 操作の精度：入口の幅、曲がり道、群れの大きさ。
- 情報量：同時に見る群れの数。
- 立て直しの重さ：混乱から戻る時間、救助可能時間。

動物を単純に速くするだけの難化は避ける。

### 16.2 標準設定

最小版は、標準設定一つでゲームの成立を確認する。次の補助設定は、最初から設計へ含める。

- 危険種の狙い動作中だけ、ゲーム速度を70%へ下げる。
- 合図の効果範囲を常に表示する。
- 自動カメラを強くする。
- 行動ボタンを大きくする。
- 緊張が高い動物を分かりやすく縁取りする。
- 失敗後に経路のヒントを表示する。

補助設定を使っても、通常のクリアと評価を可能にする。結果には使用した設定を小さく記録する。将来の競技順位では、設定別に分ける。

### 16.3 ヒント

ヒントは、最初から答えを表示しない。

- 1回目の失敗：失敗原因だけを示す。
- 同じ原因で2回失敗：注目すべき動物を示す。
- 3回失敗：安全な順序または経路を提案する。

表示前に、ヒントを見るかをプレイヤーへ選ばせる。

## 17. 初回説明

### 17.1 文章より操作で覚える

最初の説明は、画面を止めて長文を読ませる方式にしない。

- 左側を触ると主人公が動く。
- 右側を動かすとカメラが回る。
- 臆病種の反対側へ立つ。
- 誘導音を使って追従種を動かす。
- 威嚇音で危険種の注意を引く。

一つの場所で一つの内容だけを試させる。

### 17.2 最初の90秒

| 経過の目安 | 内容 |
|---|---|
| 0〜20秒 | 見晴らし台で移動とカメラを確認する |

| 45〜70秒 | 1体の追従種へ誘導音を使う |

### 17.3 再プレイ

二回目以降は、説明区画をスキップできる。操作方法は一時停止画面からいつでも確認できる。

## 18. アクセシビリティ

### 18.1 情報を一つの感覚だけへ依存させない

重要な出来事は、可能な限り二つ以上の方法で知らせる。

| 出来事 | 視覚 | 音 | 振動 |
|---|---|---|---|
| 合図が届いた | 記号、耳や顔の向き | 種類別の反応音 | 短い振動 |

| 収容完了 | 囲いの記号、残数更新 | 成功音 | 短い強めの振動 |

色、音、振動のいずれかを無効にしても、必要な情報が失われないようにする。

### 18.2 表示設定

- 文字サイズを標準と大の2段階以上で選べる。

- 動物と囲いの対応を、色と記号と形で示す。
- 画面効果、点滅、カメラ移動を減らせる。
- 状態記号を消す設定と、常に表示する設定を用意する。

### 18.3 操作設定

- 左右配置の入れ替え。
- カメラ感度と自動補正。
- ボタンとスティックの大きさ。
- 振動の有無と強さ。
- 危険時の速度低下。
- 長押し、連打、同時押しを必須にしない。

## 19. 世界観と見た目

### 19.1 暫定世界観

主人公は、自然保護区で動物の移送を担当する誘導士とする。危険種も倒す対象ではなく、安全な区域へ隔離する対象として扱う。

物語は操作を邪魔しない短い背景に留める。最小版では、開始時と結果時の短い説明だけで成立させる。

### 19.2 見た目の方向

- 丸みのある低ポリゴン表現。
- 高い視点でも種類を見分けられる大きな輪郭差。
- 緊張、警戒、追従を姿勢で読める体形。
- 地面の細部より、通れる場所と危険区域の読みやすさを優先する。
- Herdy Gerdyの固有デザイン、色、画面構成を再現しない。

### 19.3 種類ごとの見分け方

- 臆病種：横に広い体、素早い耳の動き、まとまる歩き方。
- 追従種：縦長の輪郭、主人公を見る大きな頭部、列を作る動き。
- 危険種：低い姿勢、重い足運び、遠くから分かる肩の形。

色は補助として使い、輪郭と動きだけでも判別できるようにする。

## 20. 音の設計

### 20.1 主人公の合図

誘導音と威嚇音は、音量だけでなく音の高さ、長さ、波形を明確に分ける。

- 誘導音：短く、明るく、方向を感じやすい音。
- 威嚇音：低く、広がりが分かる音。

画面には、音が届く範囲を一瞬だけ波紋で示す。

### 20.2 動物の反応音

- 反応を受け付けた音。
- 緊張が高まった音。
- 群れから離れた個体の呼び声。
- 危険種の狙いと飛びかかり。
- 囲いへ入った音。

同時に多く鳴った場合は、重要度の低い音を弱くする。危険警告と入力音を埋もれさせない。

### 20.3 初期設定

既存の開発方針に合わせ、最初の起動時は音を任意で有効化できるようにする。ブラウザの自動再生制限に従い、開始操作後に音を開始する。

## 21. 調整する数値と順序

数値は、次の順で調整する。

1. 入力から反応が見えるまでの時間。
2. 主人公の歩行、走行、旋回。
3. 接近圧力の三段階。
4. 群れのまとまりと分裂。
5. 囲いの入口と収容確定。
6. 危険種の予告と救助時間。
7. 地形ごとの経路。
8. 得点の減点幅。
9. 目標時間。
10. 見た目と音の強さ。

面白さが成立する前に、得点や目標時間を固定しない。

## 22. 開発中に記録する情報

サーバーへ送信せず、開発版の端末内または画面表示で次を確認する。

- ステージ開始、クリア、失敗の時刻。
- 失敗原因。
- 種類ごとの収容時刻。
- 混乱回数。
- 救助回数。
- 危険への曝露時間。
- 群れの分裂回数。
- 間違った囲いへの進入。
- 合図の使用時刻と反応した個体数。
- 主人公の移動距離。
- カメラを手動で回した時間。
- 詰まりからの自動復帰回数。
- 4項目の得点内訳。

この情報を使い、プレイヤーが下手だったのか、操作とカメラが悪かったのか、動物処理が不安定だったのかを分ける。

## 23. 遊びとしての試験条件

### 23.1 初回理解

初めて遊ぶ人に対し、次を目標とする。

- 30秒以内に移動とカメラを使える。
- 90秒以内に、臆病種を意図した方向へ動かせる。
- 一度合図を使った後、どの種類が反応したか答えられる。
- 失敗した場合、表示を見て原因を一つ説明できる。

### 23.2 難しさ

- 初回プレイヤーの60〜80%が、12分以内に最小版をクリアできる難しさを目標にする。
- 全員が一度で成功する場合は、順序か経路の判断を強める。
- 半数以上が同じ場所で操作不能になる場合は、操作、カメラ、入口を先に直し、難易度として扱わない。

### 23.3 再挑戦

- クリアまたは失敗後、3操作以内で再開できる。
- 二回目のプレイでは、多くのテスト参加者が得点または時間を改善できる。
- 結果画面の助言と、実際に改善できる内容が一致する。

### 23.4 複数解

- 安全な手順と速い手順の両方でクリアできる。
- どちらか一方だけが、明らかに全評価で有利にならない。
- 正解手順を暗記するだけでなく、群れの状態に応じて修正が必要になる。

## 24. 不具合と理不尽さの敵対的検証

次の操作を意図的に行い、ゲームが壊れないことを確認する。

- 入口へ主人公が立ち続ける。
- 群れを狭い角へ押し込む。
- 誘導音と威嚇音を交互に連打する。
- 危険種を囲いの入口直前で何度も引き返させる。
- 追従種を最大速度で引っ張る。
- 臆病種を二つの群れへ分断する。
- 間違った囲いへ全個体を押し込む。
- カメラを反対方向へ向けたまま移動する。
- 一時停止と再開を繰り返す。
- 救助状態の直前にやり直す。
- 画面を回転、復帰、バックグラウンド移動する。
- 20回連続で開始、失敗、再開、クリアを行う。

原因がプレイヤーに見えない失敗は、公開条件を満たさない。

作業数は増やしすぎず、最小版までを6つの大きなDraft PRで進める。

### PR 1：技術基盤と操作感の試作

**ゲーム品質の完了条件**

### PR 2：主人公、カメラ、観察

- 動的な仮想スティック。
- 歩行と走行の連続変化。

- 手動カメラを頻繁に操作しなくても基本誘導が成立する。

### PR 3：臆病種、群れ、緊張

- 圧力の三段階。

- 群れ全体と個体の分離。
- 入口予約と詰まり復帰。
- 臆病種の収容。

**ゲーム品質の完了条件**

- 正しい位置取りで、6体を再現性高く囲いへ入れられる。

### PR 4：追従種、危険種、救助

- 誘導音、威嚇音。

- 危険種の索敵、追跡、予告、飛びかかり。

**ゲーム品質の完了条件**

- ミスから救助したとき、立て直した感覚がある。

### PR 5：ステージ、説明、得点

- 最小版ステージの完成配置。
- 安全と速度の二つの有効手順。
- 初回90秒の説明。
- 4項目の得点。
- 結果画面、助言、称号、端末内記録。

**ゲーム品質の完了条件**

- 結果画面を見て、次に改善する内容が分かる。
- 速さだけではS評価を取れない。

### PR 6：見た目、音、アクセシビリティ、仕上げ

- 独自モデル、アニメーション、効果。

## 27. 完成条件

### 27.1 ゲーム性

- 3種類の違いが、見た目、反応、経路、攻略のすべてに表れる。
- 安全な手順と速い手順の少なくとも二つでクリアできる。
- 歩行と走行の使い分けが、群れの緊張と方向へ影響する。
- 合図の副作用を考える必要がある。
- 危険種を管理する理由が、文章を読まなくても理解できる。
- 失敗後、原因と改善方法が分かる。
- 二回目のプレイで、得点改善を狙える。

### 27.2 操作

- 長押し、連打、複数ボタンの同時押しを必須にしない。
- 主要ボタンは最低56×56pt、補助ボタンは最低44×44ptを目標にする。
- 移動、カメラ、合図を同時に使っても入力が取りこぼされない。
- 入力から反応表示まで100ms以内を目標にする。
- カメラが主人公と誘導対象を見失いにくい。
- 左右配置、感度、振動、画面効果を設定できる。

### 27.3 公平性

- 画面外から予告なしに失敗しない。
- 壁越しに捕食されない。
- 技術的な場外落下をプレイヤーの失敗にしない。
- 同じ条件なら、重要な初期行動を再現できる。
- 正しい操作でも偶然に詰む状態を残さない。
- 補助設定を使用しても、ゲームを最後まで遊べる。

### 27.4 得点

- 安全40%、統率25%、判断20%、時間15%で評価する。
- 速いだけの乱暴なプレイでS評価を取れない。
- 得点の減点理由を結果画面で説明できる。
- 同じ出来事を重複して減点しない。
- 最高記録と使用設定を端末内へ保存できる。

### 27.5 見た目と音

- 色だけで種類と囲いを区別しない。
- 動物の次の行動を、姿勢と予備動作から読める。
- 音なしでも危険と成功を把握できる。
- 振動なしでも情報を失わない。
- 重要な演出で操作を長く止めない。

### 27.6 技術と性能

- iPhone 17 Proで平均55フレーム毎秒以上を目標にする。
- iPhone 11 ProとiPad Pro 2018で平均30フレーム毎秒以上を目標にする。
- 動物11体で10分間安定する。
- 開発試験では20体も確認する。
- 20回連続の開始、失敗、再開、クリアで状態が壊れない。
- 型確認、単体試験、ブラウザ試験、公開用作成が成功する。

### 27.7 遊びの最終判定

次のいずれかを満たさない場合は、見た目の仕上げより先にゲーム設計を戻して修正する。

- 初めて遊ぶ人が、動物3種類の違いを説明できる。
- 失敗した人が、次に変える行動を一つ説明できる。
- クリアした人が、もう一度得点を上げたいと思える結果表示になっている。
- 開発者が想定した手順以外でも、安全な解き方が成立する。
- 操作の上達が、時間だけでなく安全と統率の得点へ表れる。
