### 0.1 廃止する旧仕様

次の旧記述は実装へ使用しない。

- 危険種の最初の攻撃を即時失敗とする。
- 動物の状態を一つの状態だけで管理する。
- 一時停止時間を無条件に得点用時間から除外する。
- ゲーム速度低下や経路ヒントを使った記録を標準記録と同列に扱う。
- 間違った囲いへ「収容確定」できる一方で、入口では必ず止める。
- 最小版から攻略結果へ影響する個体差を入れる。
- Webブラウザで振動の強さを自由に調整できる前提を置く。
- PR 6まで動物の予備動作と危険予告を仮表示しない。

| 警告区域 | 間違った囲いへの誤誘導を判定する入口手前の区域 |

## 1. 実装の基本原則

### 1.1 間接操作は予測可能でなければならない

動物は主人公の命令どおりに動く駒ではないが、結果をランダム任せにもしない。重要な行動には、開始条件、予備動作、終了条件、最大継続時間を持たせる。

### 1.2 一つのミスを複数項目へ無制限に重複減点しない

ゲーム内で起きた出来事は一度だけ記録する。得点計算はその記録を読む。毎画面、同じ状態を新しい失敗として数えない。

### 1.3 プレイヤーの失敗と技術的な不具合を分ける

経路が壊れた、場外へ落ちた、入力が解除されなかった、門を通過したのに捕獲されなかった場合は、プレイヤーの失敗や減点にしない。自動復帰または診断対象にする。

### 1.4 最小版では攻略に影響する個体差を使わない

速度、緊張しやすさ、合図への反応、通行条件は、同じ種類の全個体で同じにする。見た目の首振り、待機動作、鳴き声の間隔だけに、再現可能な小さな差を付ける。

### 1.5 数値はデータ化する

距離、時間、得点、緊張、速度、門の判定はソース内へ散らさない。種類設定、ステージ設定、得点設定へ分ける。初期値を変更しても、状態遷移のコードを書き換えない。

## 2. 1プレイの進行状態

1プレイ全体は、次の状態で管理する。

| 状態 | シミュレーション | 得点用時間 | 主な操作 |
|---|---|---|---|
| 読み込み | 停止 | 停止 | なし |
| 初回説明 | 説明対象だけ進行 | 対象外 | 説明用操作 |
| 観察 | 停止 | 最長30秒まで停止 | カメラ、目的確認 |
| 通常プレイ | 進行 | 進行 | 全操作 |
| 手動一時停止 | 停止 | 標準では進行 | 設定、再開、やり直し |
| 自動一時停止 | 停止 | 停止 | 再開確認 |
| 救助中 | 進行 | 進行 | 移動、威嚇音 |
| クリア確定 | 停止 | 停止 | 結果へ進む |
| 失敗確定 | 停止 | 停止 | 再開、結果確認 |
| 結果 | 停止 | 停止 | 再挑戦、終了 |

### 2.1 観察時間

- 観察開始から30秒以内は得点用時間を進めない。
- 主人公を動かす、誘導音を出す、威嚇音を出す、のいずれかで通常プレイへ移る。
- 30秒を過ぎた場合は、操作がなくても得点用時間を開始する。
- 初回説明の時間は得点へ含めない。

### 2.2 手動一時停止

標準記録では、手動一時停止中も得点用時間を進める。動物、危険、緊張は停止する。

これにより、何度も停止して考えることで時間評価だけを守る方法を防ぐ。

### 2.3 画面非表示とバックグラウンド移動

ブラウザが非表示になった場合は自動一時停止する。

- シミュレーションと得点用時間を停止する。
- すべての押下中入力を解除する。
- 再開前に確認画面を出す。
- 3秒を超える非表示が発生した標準記録は、補助あり記録へ変更する。
- プレイは続行できる。電話や通知を理由にゲームオーバーにはしない。

### 2.4 縦画面

通常のSafariタブで画面方向を強制できる前提にはしない。

- 縦画面ではシミュレーションを自動停止する。
- 「端末を横向きにしてください」と表示する。
- 横画面へ戻った後、入力を全解除した状態から再開する。
- 回転によって主人公や動物の状態を初期化しない。

## 3. プレイモードと記録の分離

| モード | 使用できる補助 | 得点 | 保存先 |
|---|---|---|---|
| 標準 | 文字、色、左右配置、ボタンサイズ、音、振動、通常のカメラ設定 | あり | 標準記録 |
| 補助あり | 危険時速度低下、常時範囲表示、強い危険縁取り、強い自動カメラ | あり | 補助あり記録 |
| 練習 | 得点用時間停止、経路ヒント、状態常時表示、途中から再開 | なし | 練習履歴のみ |

### 3.1 標準記録へ含めてよい設定

次は難しさを直接下げないため、標準記録で利用できる。

- 文字サイズ
- 色覚に配慮した表示
- 音の有無と音量
- 振動の有無
- 左右配置の入れ替え
- 仮想スティックとボタンの大きさ
- カメラ左右反転
- 通常範囲内のカメラ感度
- 画面効果と点滅の削減

### 3.2 補助あり記録へ切り替える設定

次は判断時間または情報量を増やすため、標準記録と分ける。

- 危険種の狙い中にゲーム速度を70%へ下げる
- 合図と接近圧力の範囲を常時表示する
- 危険対象を通常より強く表示する
- 自動カメラが危険対象を積極的に追う
- 失敗前に経路または順序の具体的警告を出す

補助ありでもS評価を取得できる。ただし、標準Sと補助ありSは別に保存する。

## 4. 入力の正式仕様

### 4.1 指の所有権

左スティック、右カメラ、誘導音、威嚇音は、それぞれ一つの指の識別番号を所有する。

- 左側の移動領域から始まった指は、指を離すまで移動専用とする。
- 右側のカメラ領域から始まった指は、後からボタン上へ移動しても合図を発動しない。
- 合図ボタン上から始まった指は、カメラ操作へ変更しない。
- 一つの指を複数の操作へ割り当てない。
- `pointerup`、`pointercancel`、画面非表示、画面回転で所有権を必ず解除する。

### 4.2 合図ボタン

- 指を置いた時点で、発動予定範囲を薄く表示する。
- 指を離した時点で発動する。
- 指をボタン外へ一定距離滑らせて離すと取り消す。
- 押下中に別の画面を開いた場合は取り消す。
- 発動受付から100ms以内に、波紋、ボタン反応、動物の顔向けのいずれかを開始する。

### 4.3 移動方向とカメラ

主人公の移動はカメラ基準とする。ただし、自動カメラによって進行方向が勝手に変わらないよう、次の規則を使う。

1. スティックを置いた時点のカメラ水平向きを、移動基準として保存する。
2. スティックを操作中、自動カメラの回転は移動基準へ反映しない。
3. 右指で手動カメラを回した場合だけ、移動基準を滑らかに更新する。
4. スティックを離した後、現在のカメラ向きを次の操作基準にする。

### 4.4 歩行と走行

- スティック入力0〜0.25：停止領域
- 0.25〜0.68：歩行
- 0.68〜1.00：歩行から走行へ連続変化
- 急に走行へ切り替えず、0.15秒程度で加速する
- 精密操作設定では、歩行領域を広げる

### 4.5 ブラウザ操作との競合

- ゲーム操作領域ではブラウザのスクロール、選択、長押しメニューを発生させない。
- 画面端にはOS操作と競合しにくい余白を置く。
- 右下ボタンは安全領域内へ置く。
- 画面回転後に押下状態を復元しない。

## 5. 誘導手段の正式仕様

数値は最初の実機試験で調整できるが、重ね掛けと優先順位の規則は変更しない。

### 5.1 接近圧力

| 範囲 | 初期距離 | 反応 |
|---|---:|---|
| 注意 | 5.5m | 主人公を見る。大きく移動しない |
| 誘導 | 3.5m | 反対方向へ歩く |
| 緊迫 | 1.5m | 走って離れ、緊張が大きく上がる |

- 走行中の圧力は歩行時の1.35倍を初期値とする。
- 壁の反対側にいる動物へ接近圧力を与えない。
- 複数の主人公は存在しないため、圧力源は一つだけとする。

### 5.2 誘導音

| 項目 | 初期値 |
|---|---:|
| 追従継続 | 5秒 |
| 再使用待ち | 1秒 |
| 重ね掛け | 残り時間を5秒へ更新。加算しない |
| 判定 | 発動瞬間の1回 |

- 追従種だけが本格的に追従する。
- 臆病種は一瞬見るが、追従しない。
- 危険種は通常時は無視する。
- `soundBlocker`と指定した壁だけが音を遮る。
- 小さな木、草、装飾物で音を遮らない。

### 5.3 威嚇音

| 項目 | 初期値 |
|---|---:|
| 危険種が主人公を優先する時間 | 4秒 |
| 再使用待ち | 3秒 |
| 効果終了後の通常耐性 | 1.75秒 |
| 重ね掛け | 継続時間を4秒へ更新。加算しない |
| 判定 | 発動瞬間の1回 |

- 臆病種は短時間散開し、緊張が上がる。
- 追従種は追従を解除し、近くで待つ。
- 危険種は保護対象より主人公を優先する。
- 通常耐性中は、再び主人公へ引きつけられない。
- 救助中は、同じ救助出来事につき1回だけ耐性を無視できる。
- 救助で使った特例は、出来事記録へ残す。

### 5.4 同じ時刻に複数の合図が届いた場合

同じ動物へ同じシミュレーション更新内で複数の合図が届いた場合は、次の順で処理する。

1. 救助用の威嚇音
2. 通常の威嚇音
3. 誘導音
4. 接近圧力

低い優先の合図も「受信した」表示は出せるが、行動目的を上書きしない。

## 6. 緊張と混乱

### 6.1 最小版の方針

緊張値は種類の基本値だけで計算し、攻略に影響する個体差を使わない。緊張が増えた原因を必ず記録する。

### 6.2 緊張の主原因

| 原因 | 記録名 | 主に影響する得点 |
|---|---|---|
| 主人公が近すぎる | `playerPressure` | 安全 |
| 威嚇音で散らされた | `threatSignal` | 安全 |
| 危険種を視認した | `predatorExposure` | 危険管理 |
| 群れから孤立した | `isolation` | 統率 |
| 通れない場所へ押された | `blockedPath` | 統率または不具合診断 |

同時に複数原因がある場合は、増加量が最も大きい原因を主原因として記録し、残りは補助原因として保持する。

### 6.3 状態の切り替え

値が境界付近で細かく往復しないよう、入る値と戻る値を分ける。

| 心理状態 | 入る条件 | 戻る条件 |
|---|---|---|
| 平静 | 初期状態、または緊張30以下 | 緊張45以上で警戒へ |
| 警戒 | 緊張45以上 | 30以下で平静へ、85以上で混乱へ |
| 混乱 | 緊張85以上 | 最低1.5秒継続後、55以下で警戒へ |

60以上は得点計測用の高緊張区域として扱うが、心理状態の切り替え境界には使わない。

### 6.4 回復

- 緊張要因がない場合、毎秒12を初期回復量とする。
- 主人公が注意範囲より外にいて、危険種も見えず、仲間の近くにいる場合は毎秒18まで回復できる。
- 混乱の最低継続中は、誘導音と接近圧力で進行方向を細かく変更しない。
- 混乱中でも、崖、壁、捕食者からの即時回避は有効とする。

## 7. 状態の4層管理

動物の状態は一つの列挙値へまとめない。次の4層を同時に持つ。

| 層 | 主な状態 |
|---|---|
| 生存・収容 | 活動中、救助待ち、収容中、収容済み、失敗確定 |
| 行動目的 | 待機、通常移動、群れ復帰、主人公から逃走、主人公へ追従、捕食追跡、囲い進入 |
| 心理 | 平静、警戒、混乱 |
| 移動 | 停止、移動中、入口待ち、道を探し直す、自動復帰 |

詳細な開始条件、終了条件、割り込み条件は`docs/STATE_TRANSITION_SPEC.md`へ定める。

### 7.1 優先順位

毎回の判断では、次の順に解決する。

1. 収容済み、失敗確定
2. 救助待ち
3. 危険種の狙い、飛びかかり、攻撃後回復
4. 崖、壁、場外などの即時危険
5. 捕食者からの逃走
6. 主人公の合図
7. 群れへの復帰
8. 通常行動

### 7.2 状態変更の記録

状態が変わるたびに、次を記録する。

- 動物識別子
- 変更前と変更後
- シミュレーション時刻
- 変更理由
- 原因となった主人公、合図、危険、囲い、地形

同じ状態へ繰り返し設定しただけでは、新しい出来事を作らない。

## 8. 危険種の攻撃と救助

### 8.1 攻撃段階

| 段階 | 初期時間 | 開始条件 | 中断条件 |
|---|---:|---|---|
| 索敵 | 継続 | 攻撃可能な対象がいない | 対象発見 |
| 追跡 | 継続 | 視認可能で経路がある | 対象喪失、威嚇音、収容 |
| 狙い | 最低1.2秒 | 攻撃距離内、視線が通る | 対象喪失、威嚇音、壁、経路消失 |
| 飛びかかり | 約0.45秒 | 狙い完了時も視線が通る | 原則中断しない。壁へ当たれば失敗 |
| 攻撃後回復 | 1秒 | 飛びかかり終了 | 時間経過 |

- 飛びかかり開始時に、対象までの直線と衝突可能性を再確認する。
- 壁越し、経路なし、収容済み、場外復帰中の対象を選ばない。
- 狙い開始時に、画面内表示、画面端表示、警告音のうち最低2つを出す。

### 8.2 保護対象への最初の攻撃

最初の有効攻撃は即失敗にしない。

- 対象を救助待ちへ移す。
- 救助可能時間は3秒を初期値とする。
- 対象はその場で倒れ、移動と収容を停止する。
- 危険種は0.6秒の攻撃後回復へ入る。
- 主人公が威嚇音を当てる、または救助影響範囲へ入り危険種の注意を引くことで救助する。
- 救助成功後、対象は1秒の保護時間を持ち、その間は再攻撃対象にならない。

### 8.3 失敗確定

次のいずれかで失敗する。

- 3秒以内に救助できない。
- 救助待ちが存在する間に、別の保護対象へ有効攻撃が成立する。
- 救助後の同じ対象が、保護時間終了後に再び有効攻撃を受ける。

最小版では、1プレイ中に同じ対象を何度も救助する無限立て直しを許可しない。

### 8.4 主人公への攻撃

危険種が主人公へ追いついた場合はゲームオーバーにしない。

- 主人公を0.5秒程度よろめかせる。
- 危険種の主人公優先を解除する。
- 危険種を1秒の攻撃後回復へ入れる。
- 主人公は囲い入口を物理的に塞ぐ障害物として使えない。

## 9. 囲い、門、収容

### 9.1 通常動物の収容確定

次をすべて満たした場合に収容中へ移る。

1. 動物の中心が収容確定線を越える。
2. 進行方向と囲い内向きの内積が0より大きい。
3. 動物の中心が0.35秒以上、囲い内側に留まる。
4. 対応する種類の囲いである。

収容中は数歩奥へ進み、1秒以内に収容済みへ移る。収容済み後は外へ戻らない。

### 9.2 間違った囲い

対応しない囲いへ収容確定しない。

- 入口手前の警告区域へ1秒以上留まると、`wrongPenGuidance`を1回記録する。
- 動物は首振りなどの拒否動作を出し、少し後退する。
- 同じ動物と同じ囲いの組み合わせでは、5秒以内の再進入を同じ出来事として扱う。
- ユーザー向けには「誤収容」ではなく「誤誘導」と表示する。

### 9.3 危険種の収容確定

危険種は次の5条件をすべて満たした場合だけ収容する。

1. 危険種の中心が専用囲いの内側確定線を越える。
2. 危険種の当たり判定全体が囲い内部へ入る。
3. 主人公が狭い逃げ道から囲い外へ出る。
4. 危険種が囲い内部へ0.6秒以上留まる。
5. 門を閉じられる空間へ主人公と他の動物が入っていない。

条件成立と同じシミュレーション更新で、次を行う。

- 門の見た目を閉鎖開始へする。
- 門の通行禁止を有効にする。
- 危険種を収容済みへする。
- 危険種の索敵、追跡、攻撃を停止する。
- 収容成功の出来事を一度だけ記録する。

### 9.4 囲い入口の通行権

- 一つの入口につき、一度に1体だけ先頭として予約する。
- 後続は入口手前で間隔を保つ。
- 予約は2秒進展がなければ解除する。
- 3秒以上進めない個体は一度横へ離れ、並び直す。
- 予約中の動物が場外復帰または救助待ちへ移った場合は即解除する。

## 10. 衝突の正式規則

### 10.1 衝突表

| 組み合わせ | 規則 |
|---|---|
| 主人公 × 地形・柵・閉じた門 | 通過不可 |
| 主人公 × 通常動物 | 強い押し出しなし。動物が柔らかく回避する |
| 主人公 × 危険種 | 接触はよろめき。身体で入口を固定できない |
| 通常動物 × 地形・柵・閉じた門 | 通行地図と近接回避で通過不可 |
| 通常動物 × 通常動物 | 柔らかい距離確保。物理的な積み重なりなし |
| 危険種 × 通常動物 | 通常は近接回避。飛びかかり時だけ攻撃判定 |
| 収容済み動物 × すべて | 囲い内の表示用。外部の道順と押し合いへ影響しない |

### 10.2 主人公による入口塞ぎ対策

- 主人公は動物の進行方向を完全に止める物理壁にならない。
- 動物は主人公との距離が近い場合、横へ回る進路を選ぶ。
- 主人公が入口中央へ1秒以上立つと、「入口を空ける」表示を出す。
- 主人公が入口に立つことで危険種を固定し、門条件を成立させることはできない。

### 10.3 場外と復帰

- 技術的な場外落下を失敗や減点にしない。
- 最後に安全だった位置を最大2秒ごとに記録する。
- 場外時は自動復帰へ移り、その位置へ戻す。
- 復帰中は捕食、収容、得点判定を無効にする。
- 自動復帰回数を診断へ記録し、1プレイ中に1回でも発生した場合は公開前に原因を調査する。

## 11. カメラの正式仕様

### 11.1 現在の対象群れ

カメラが参照する対象群れは、毎画面もっとも近い群れへ切り替えない。

- 最後に有効な合図へ反応した群れを現在対象とする。
- 一度選んだ対象を最低1秒維持する。
- 合図の効果終了後も6秒まで保持する。
- 対象群れが収容済み、救助待ち、完全に分裂した場合は再選択する。
- 群れが分裂した場合は、収容目標へ近い主要群を対象とし、離れた個体は画面端表示で知らせる。

### 11.2 注視点

主人公65%、現在対象群れ35%を初期値とする。これは固定式ではなく、次で調整する。

- 主人公と群れの距離が近い：主人公寄り
- 距離が離れる：群れ比率とカメラ距離を少し増やす
- 危険種が画面内に見える：カメラを動かさず警告表示を優先
- 狙い中の危険種が画面外：急回転せず、注視点を小さく寄せる

### 11.3 速度制限

カメラの回転、移動、拡大縮小へ上限を持たせる。対象切り替え時に瞬間移動しない。

- 手動操作終了後1.5秒は自動補正を弱める。
- 急な危険警告でも、180度の自動回転を行わない。
- 遮蔽物は透過または距離調整で対応し、カメラを地形内部へ入れない。

### 11.4 カメラ品質の判定

基本誘導中に手動カメラを操作している時間が、全操作時間の20%を超える場合は、プレイヤーの技量ではなくカメラ設計の問題として扱う。

## 12. 得点の正式仕様

### 12.1 出来事記録を唯一の計算元にする

得点は動物の現在状態を毎画面直接読むのではなく、1プレイ内の出来事記録から計算する。

各出来事は次を持つ。

- 一意な出来事識別子
- 種類
- 発生時刻と終了時刻
- 原因
- 対象動物、群れ、危険種、囲い
- 重複をまとめるための出来事グループ
- 標準、補助あり、練習の区分

同じ識別子の出来事を二度加算しない。

### 12.2 総得点

| 評価 | 最大点 | 比率 |
|---|---:|---:|
| 安全 | 40,000 | 40% |
| 統率 | 25,000 | 25% |
| 危険管理 | 20,000 | 20% |
| 時間 | 15,000 | 15% |

旧称の「判断評価」は、実際の内容に合わせて「危険管理評価」へ変更する。

### 12.3 安全評価

40,000点から始める。

| 出来事 | 減点 |
|---|---:|
| 救助待ちの発生 | 1回10,000 |
| 主原因が主人公圧力または威嚇音の混乱 | 1出来事1,200 |
| 主原因が主人公圧力または威嚇音で、緊張60以上だった時間 | 1秒50、最大8,000 |

危険種の視認が主原因の高緊張時間は、危険管理へ含め、安全へ重複計上しない。

### 12.4 統率評価

- 基礎点：10,000
- 種類ごとの清潔な収容：1種類につき5,000
- 誤誘導：1出来事につき4,000減点
- 主原因が主人公誘導、孤立、経路選択である群れ分裂：1出来事につき1,500減点

危険種から逃げた結果として分裂した場合は、統率へ重複減点せず、危険管理の出来事として扱う。

### 12.5 危険管理評価

20,000点から始める。

- 危険種が保護対象を視認し、経路が成立している曝露時間：1秒100減点
- 狙い段階の開始：1出来事2,000減点
- 危険種収容後に危険判定が再発した場合：得点ではなく不具合として記録

連続した同一追跡は一つの危険出来事グループにまとめる。対象を失い2秒以上経過した後の再追跡は新しい出来事とする。

### 12.6 時間評価

- `parTime`以内：15,000
- `slowTime`以上：3,000
- その間：3,000〜15,000を単調に減少させる
- `parTime`と`slowTime`はプレイ試験前に固定しない
- 手動一時停止中も、標準記録では得点用時間を進める
- 初回説明は除外する
- 観察は最大30秒まで除外する
- バックグラウンド移動が3秒を超えた記録は補助ありへ移す

### 12.7 評価段階

| 評価 | 条件 |
|---|---|
| S | 90,000以上、救助なし、誤誘導なし |
| A | 75,000以上 |
| B | 60,000以上 |
| C | クリア |

標準、補助ありの評価は別に保存する。練習では得点評価を確定しない。

### 12.8 得点の範囲

- 各項目は0未満にしない。
- 総得点は0〜100,000に収める。
- 救助失敗でゲームオーバーになった場合、正式なクリア得点を保存しない。
- やり直し時は、その1プレイの出来事記録と得点計算を完全に破棄する。

## 13. 初回説明

時間経過だけで説明を進めない。次の達成条件で進める。

1. 主人公を一定距離動かした。
2. カメラを一定角度動かした。
3. 臆病種を目的方向へ一定距離動かした。
4. 追従種が誘導音へ反応し、主人公を追った。
5. 危険種が威嚇音で主人公を向いた。

90秒は初見プレイヤーが終えられる目標時間として使い、強制進行には使わない。

### 13.1 説明中の安全

- 説明対象以外の動物と危険種は進行を停止する。
- 説明用動物は本番得点へ含めない。
- 説明をスキップした場合は本番開始位置へ正しく初期化する。
- 二回目以降はスキップできる。

## 14. 音と振動の実装条件

### 14.1 音

- 最初のユーザー操作後に音声機能を開始する。
- 音が開始できなくてもゲームを進行できる。
- 危険、合図、収容を視覚でも伝える。
- 同時音数に上限を設け、危険警告と入力音を優先する。

### 14.2 振動

- 実行時に利用可能か確認する。
- 利用できない場合は何も起こさず、エラーにしない。
- 最小版の設定は原則として有効・無効とする。
- 強さを自由に制御できる前提を置かず、短い、二連などのパターン差で表現する。
- 振動だけで重要情報を伝えない。

## 15. 再現、診断、共有

乱数の種だけでは不具合を再現できない。開発版では1プレイごとに次を記録する。

- ビルドのコミット番号
- 設計仕様版とデータ形式版
- ステージデータの識別値
- 乱数の種
- プレイモードと設定
- 固定更新ごとの移動入力
- 合図の押下、取り消し、発動時刻
- 一時停止、画面非表示、画面回転
- 動物の状態変更
- 経路再探索と自動復帰
- 出来事記録
- 得点の内訳
- 画面更新速度、判断処理時間、メモリの目安

### 15.1 診断データの共有

開発画面へ「診断データを共有」を用意する。

- JSONとして出力する。
- iPhoneの共有シートまたはクリップボードを使用する。
- 個人情報、秘密情報、認証情報を含めない。
- 通常公開画面では、開発用指定がない限り表示しない。

### 15.2 再現条件

同じビルド、ステージ、設定、乱数、入力履歴を使った場合、重要な状態変更と得点出来事が同じ固定更新で発生することを目標にする。

## 16. 自動試験で守る不変条件

特定の正解手順だけでなく、どの入力でも破ってはいけない条件を試験する。

- 収容済み動物が囲い外へ戻らない。
- 危険種が壁越しに攻撃しない。
- 経路がない対象へ飛びかからない。
- 収容済み、場外復帰中、説明用の動物を攻撃対象にしない。
- 一つの入口へ同時に複数の通行予約を与えない。
- 得点が0未満または100,000超にならない。
- 同じ出来事を二重に減点しない。
- 位置、速度、緊張、得点が計算不能な値にならない。
- 3秒以上詰まった個体が並び直しまたは再探索へ移る。
- 一時停止中にシミュレーション状態が進まない。
- やり直し後に前回の状態、出来事、得点が残らない。
- `pointercancel`、画面非表示、画面回転後に押下入力が残らない。
- 危険種収容後に索敵と攻撃が再開しない。

### 16.1 攻撃的な自動操作

移動、合図、停止、再開をランダムに組み合わせた自動実行を多数行い、次を探す。

- 進行不能
- 無限状態切り替え
- 合図の永久延長
- 得点の重複
- 門のすり抜け
- 動物の場外
- メモリの増加
- 画面非表示からの復帰不良

## 17. 6つのDraft PRと中止判定

作業数は6つの大きなDraft PRを維持する。ただし、各PR内に次工程へ進まないための判定を設ける。

### PR 1：技術基盤と入力適合

**実装**

- TypeScript、Vite、Three.js
- Navcat、three-mesh-bvh
- 固定更新と診断の基礎
- 指の所有権、入力解除、横画面案内
- 音開始と振動の利用可否確認

**中止判定**

- iPhone Safariで入力が残る、2本指操作が競合する、10分間停止する場合は、動物実装へ進まない。
- Navcatが入口、種類別通行、メモリの条件を満たさない場合は、同じPR内で予備案へ切り替える。

### PR 2：主人公、カメラ、観察

**実装**

- 動的スティック、歩行、走行
- 移動基準の固定
- 対象群れを想定したカメラ枠組み
- 観察時間、手動一時停止、自動一時停止
- 遮蔽物と縦画面復帰

**中止判定**

- 主人公1人と仮動物1体で、移動とカメラが意図どおりにならない場合は群れへ進まない。
- 基本操作中の手動カメラ時間が20%を超える場合はカメラを直す。

### PR 3：臆病種と群れ

**実装順**

1. 臆病種3体、平地、接近圧力だけ
2. 臆病種6体、群れ、入口予約
3. 緊張と混乱
4. 仮の予備動作と状態表示

**中止判定**

- 3体を意図した方向へ再現性高く動かせない場合は、6体、緊張、混乱へ進まない。
- 6体の収容が正しい操作でも5回中1回以上詰まる場合は、群れと入口を先に直す。

### PR 4：追従種、危険種、救助

**実装順**

1. 主人公、危険種、専用囲いだけで捕獲を成立させる
2. 誘導音、威嚇音、再使用、耐性
3. 攻撃予告、飛びかかり
4. 救助
5. 追従種を加えた統合
6. 仮の予告動作、警告音、画面端表示

**中止判定**

- 危険種単体を意図どおり捕獲できない場合は、救助や追従種へ進まない。
- 画面外、壁越し、経路なしの攻撃が一度でも起きる場合は統合へ進まない。

### PR 5：ステージ、説明、得点

**実装順**

1. 11体の仮表示で安全手順と高速手順を確認
2. 出来事記録
3. 得点
4. 初回説明
5. 標準、補助あり、練習の保存分離
6. 結果の助言

**中止判定**

- 二つの有効手順が成立しない場合は得点を固定しない。
- 得点の重複減点を説明できない場合は結果画面へ進まない。
- 初見テストで同じ場所に半数以上が止まる場合は、難易度ではなく操作、カメラ、配置を直す。

### PR 6：見た目、音、アクセシビリティ、公開

**実装**

- 仮動作を完成モデルとアニメーションへ置き換える
- 音、任意の振動
- 表示と設定
- 負荷改善
- 自動試験、実機試験、攻撃的検証
- ライセンス記録

**中止判定**

- 見た目の変更によって種類や予備動作が読みにくくなった場合は、公開しない。
- 性能目標、入力解除、状態不変条件のいずれかを満たさない場合は、公開しない。
